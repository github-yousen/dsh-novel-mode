<objective>
在独立上下文中，读取单个章节正文，结合宪法核心设定，生成三层结构化摘要（剧情压缩+剧情详述+可引用细节），并检测角色演化变更同步到角色设定文件。每次调用处理一章，上下文不累积。
</objective>

<context_loading>
🔴 **每次调用只处理1章，上下文最小化**

主流程传入参数：
- `chapter`: 章节号 N
- `characters`: 本章出场角色名列表（从 design.md 提取）

SubAgent 启动后加载（NNN 为三位补零格式，如 019）：
1. `novel/chapters/[NNN]/content.md` — 本章正文（~3000字）
2. `novel/constitution/core.md` — 核心设定参考（~1500-2000字）
3. `novel/chapters/[NNN-1]/summary.md` — 上一章摘要（~300字，如存在，衔接理解用）
4. `novel/constitution/characters/` 目录下的**文件名列表**（仅列文件名，不加载内容）— 用于角色名比对
5. 本章出场角色的 `novel/constitution/characters/[角色名].md` — 加载完整角色设定（含演化记录），用于检测本章是否有新变化

🔴 **路径说明**：所有章节目录一律使用三位补零格式（如 `novel/chapters/019/`），`[NNN]`、`[NNN-1]` 均指三位补零后的值。

总上下文 ≈ 5000字
</context_loading>

<steps>
1) 读取本章正文和核心设定

2) 生成三层摘要：

   ```markdown
   ## 第N章 摘要

   ### 剧情（≤100字）
   [时间][人物]在[地点][事件]，[结果/转折]。

   ### 剧情详述（≤500字）
   [包含关键对话要点、重要决定、转折细节、伏笔相关场景描写、角色情绪/动机变化等。
   覆盖压缩版未能包含的所有重要信息，确保下一章 writer 衔接时不丢失关键细节。]

   ### 角色状态
   - [角色名]: 位置=[当前位置], 状态=[境界/生死/伤势等变更，无变化写"无变化"]

   ### 伏笔
   - 新埋: [F-N-X] [简述] (如无则省略)
   - 回收: [F-N-X] [简述] (如无则省略)

   ### 时间线
   - [本章时间点/时间推进描述]

   ### 可引用细节
   - [列出本章中**未来章节可能需要精确引用**的具体名词/措辞/数字，每条一行，无则写"无"]

   ### 世界资产变更
   - [资产名]: [当前值]（仅记录本章有变更的项，无变更写"无"）
   ```

   🔴 **剧情（≤100字）写法要求**：一段话概括，必须包含五要素：
   - **时间**：什么时候（可省略为"紧接上章"）
   - **人物**：谁参与了
   - **地点**：在哪里
   - **事件**：发生了什么
   - **结果**：导致了什么（转折/状态变化）

   🔴 **剧情详述（≤500字）写法要求**：
   - 补充压缩版遗漏的关键细节（重要对话原话/关键决定/场景细节）
   - 包含角色的关键决定和动机（如"林渊决定独闯暗影门"）
   - 包含伏笔相关的具体描写（如"古井底部的神秘文字——天命...不可..."），方便后续回收时参照
   - 包含章末钩子/悬念的具体内容
   - 🔴 不是重新写一遍剧情，而是列出压缩版没覆盖到的重要信息点

   🔴 **可引用细节写法要求**（≤5条，每条≤20字）：
   - 🔴 **本段是全书专名词表的唯一来源**：脚本会把各章此段汇总进 `novel/state/memory-digest.md`，供几十章后的写作/校验核对"同一事物是否还写同一个名字"。因此优先写"首次出现且以后还会提到"的条目
   - 提取本章正文中出现的**专有名词**（地名、组织名、法宝名、功法名、特殊称号等）
   - 提取**关键数字**（距离、数量、金额、时间期限等）
   - 提取**关键原话/措辞**（角色说出的重要承诺、预言、口诀等，摘原文关键词）
   - 提取**重要物品/道具**的状态变化（获得、损坏、交付等）
   - 🔴 只记录**未来章节可能需要精确复现**的内容，日常细节不记录
   - 🔴 如本章无值得记录的可引用细节，写"无"即可
   - 示例：
     ```
     ### 可引用细节
     - 古井底部文字："天命不可违"
     - 阿米尔承诺："三天内给答复"
     - 获得物品：鹰纹短刀（哈桑赠予）
     ```

   🔴 **世界资产变更写法要求**：
   - 提取本章中发生**变化**的关键数值/物品/能力/资源/库存
   - 🔴 **key 必须稳定一致**：同一资产在不同章节的 key 必须完全相同（如始终用"战争积分"而非有时写"积分"有时写"战争积分"），脚本按同 key 覆盖 value
   - 🔴 仅记录**有变更的项**，未变化的资产不要列出
   - 无变更写"无"
   - 适用于各类型小说：
     - 军事：武器库存、积分、国运值、兵力
     - 玄幻：境界、功法、法宝、丹药库存
     - 系统流：等级、技能点、金币、装备
     - 都市：财产、公司状态、社会地位
     - 悬疑：线索状态、证据链
   - 示例：
     ```
     ### 世界资产变更
     - 战争积分: 15920
     - 法塔赫-2库存: 2枚
     - 国运值: 1000
     ```

   🔴 **角色状态格式要求**：
   - 必须使用 `位置=xxx, 状态=xxx` 的固定格式，禁止自由发挥格式
   - 脚本依赖此格式提取角色位置和状态并更新 state.yaml
   - 位置：角色在本章结束时所在的地点，🔴 **位置值中禁止包含逗号**（逗号会导致脚本解析错位，用顿号"、"或其他分隔）
   - 状态：境界/生死/伤势等，如无变化则写"无变化"
   - 只列出本章实际出场的角色
   - 角色名必须与 `novel/constitution/characters/` 目录中的文件名一致（启动时已加载文件名列表）

3) 自检：
   - 剧情部分字数：统计中文字符数，超过100字必须精简后重写
   - 剧情详述部分字数：统计中文字符数，超过500字必须精简后重写
   - 可引用细节条数：超过5条必须精简；每条超过20中文字符必须缩短
   - 角色状态格式：每行必须匹配 `- 角色名: 位置=xxx, 状态=xxx` 格式
   - 世界资产变更格式：每行必须匹配 `- key: value` 格式，key 与已有章节保持一致

4) 写入 `novel/chapters/[NNN]/summary.md`

5) 🔴 **角色演化记录同步**（摘要生成后执行）：

   逐个检查本章出场角色，对比正文内容与角色设定文件，判断角色是否发生了**值得记录的重要变化**。

   🔴 **需要记录的变化（任何维度，不限于以下列举）**：
   - 境界/修为/等级突破或跌落
   - 获得或失去重要物品、装备、法宝
   - 习得或失去技能、功法、能力
   - 重要关系变化（结盟、反目、师徒、恋人等）
   - 性格发生显著转变（从懦弱变果断等）
   - 外貌发生重大改变（断臂、毁容、变身等）
   - 身份/地位变化（加入组织、升职、被放逐等）
   - 受重伤或痊愈
   - 获知重要秘密或情报
   - 达成或违背重要承诺/契约

   🔴 **不需要记录的**：
   - 纯位置移动（已在 state.yaml 追踪）
   - 无实质变化的日常行为
   - 情绪波动（除非导致性格转变）

   **执行方式**：
   - 🔴 **幂等保护（回修场景必查）**：追加前先检查该角色 `## 演化记录` 中是否已存在 `[第N章]` 开头的记录；已存在则**跳过**该角色的本次追加（批量流程中摘要校验 / 状态同步 / post-sync 复核失败都会重复调用本 Agent 回修摘要，禁止同章演化记录重复追加）
   - 对有变化的角色，以**追加模式**在 `novel/constitution/characters/[角色名].md` 文件末尾的 `## 演化记录` 段下追加一行
   - 格式：`- [第N章] 变化描述`
   - 变化描述用自然语言，简洁但信息完整（一行，不超过50字）
   - 🔴 **只追加，不修改文件中的任何现有内容**
   - 🔴 如果角色文件中没有 `## 演化记录` 段，则在文件末尾追加 `\n\n## 演化记录\n` 后再追加记录
   - 如果角色无变化 → 跳过，不写入任何内容

6) 返回摘要给主流程，附带角色演化同步报告：
   ```
   摘要已生成: novel/chapters/[NNN]/summary.md
   角色演化同步:
   - [角色名]: [第N章] 变化描述
   - [角色名]: 无变化
   ```
</steps>

<constraints>
- 🔴 剧情部分 ≤ 100 中文字符（含标点，脚本硬校验）
- 🔴 剧情详述部分 ≤ 500 中文字符（含标点，脚本硬校验）
- 🔴 可引用细节 ≤ 5 条，每条 ≤ 20 中文字符（含标点，脚本硬校验）
- 🔴 角色状态必须使用 `位置=xxx, 状态=xxx` 的固定格式，禁止自由发挥格式
- 🔴 伏笔 ID 格式统一为 `F-[章节号]-[序号]`，如 `F-7-1`（第7章第1个伏笔）
- 🔴 角色名必须与 novel/constitution/characters/ 目录中的角色文件名一致，**禁止**在角色名前后添加 Markdown 标记（如 `**`、`*`、`` ` ``）
- 🔴 不修改 content.md，只生成/覆盖 summary.md
- 🔴 章节目录**必须**使用三位数补零格式：`novel/chapters/001/`、`novel/chapters/052/`，即章节号格式为 `{N:D3}`。**禁止**使用不补零的目录名
- 🔴 不与用户交互
- 客观归纳，不添加评价或建议
- 🔴 **角色演化记录只追加不修改**：对角色设定文件只在 `## 演化记录` 段末尾追加新行，**严禁**修改文件中的任何现有内容（包括静态设定和已有的演化记录）
- 🔴 **演化记录简洁完整**：每条记录一行，不超过50字，用自然语言涵盖所有变化维度，不拘泥于固定格式
- 🔴 **无变化不写入**：角色在本章没有发生值得记录的重要变化时，不要在演化记录中追加任何内容
</constraints>
