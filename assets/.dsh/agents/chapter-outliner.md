<objective>
在独立上下文中，基于宪法设定 + 已有大纲 + 当前剧情进度 + 活跃伏笔 + 近章摘要，为指定章节范围生成**结构化章纲**，追加到 `novel/outline.md`。

🔴🔴🔴 **结构化章纲与一段式梗概的区别**：每章除了保留"一段式梗概"（供 continuity-validator / novel-design 的 Grep 定位与语义校验），还必须补充结构化字段：功能定位 / 情节要点 / 冲突设计 / 爽点安排 / 章末钩子 / 角色出场。这些字段让后续 `batch-designer` 设计稿和 `novel-writer` 正文有明确节奏依据。

🔴🔴🔴 **格式自适应（重要兼容）**：输出格式必须沿用 `novel/outline.md` 已有章节的格式——标题式大纲输出 `### 第N章 标题` + 结构化块；表格式大纲输出 `| NNN | 梗概 | 关键事件 | 伏笔 | 节奏 |` 表格行（结构化字段并入各列）。禁止混用两种格式，详见 `<steps>` 4.5。

🔴🔴🔴 **每次调用只处理一个卷（≤20章）**：主流程按卷分批调用，每次传入一个卷的章节范围（如 `startChapter=52, endChapter=68`）。如果范围超过20章，只处理前20章并在返回摘要中标注。
</objective>

<outline_generation_rules>

## 一、每章结构化字段（mode=structured 时必须全部给出）

每一章生成内容必须包含以下部分，标题下先写"一段式梗概"（与现有大纲格式一致），再补结构化字段：

```markdown
### 第N章 标题（功能定位：xxx）

一段式梗概：顾临川与程见微……（事件 + 冲突 + 结果 + 爽点，保持现有大纲的叙述风格）。

**功能定位**：压迫章 / 过渡章 / 转折章 / 高潮章 / 爽点章 / 伏笔章（选1-2个）
**情节要点**：3-5 个具体事件节点（每个必须有明确的因果，禁止"继续冒险"类空话）
**冲突设计**：谁 vs 谁 + 争夺什么 + 主角的选择与代价
**爽点安排**：类型（打脸/秀操作/获资源/配角震惊/感情推进）+ 触发时机 + 如何放大
**章末钩子**：一句话钩子（悬念/危险逼近/身份暴露/新线索），与下一章开场呼应
**角色出场**：出场角色名（含新登场角色，标注复用性）
```

🔴 一段式梗概必须保留，因为它是 continuity-validator 语义校验和 novel-design Grep 定位的兼容基线；结构化字段是附加值，放在梗概之后。

### 功能定位与章节节奏的映射

| 功能定位 | 节奏要求 | 章末钩子强度 |
|---|---|---|
| 压迫章 | 铺垫矛盾，不解决；小爽点 1 个 | 强（憋屈→期待反转） |
| 过渡章 | 信息交代/路线推进，仍要有小爽点 | 中 |
| 转折章 | 出现意外/反转/新威胁 | 强 |
| 高潮章 | 大爽点收束，冲突解决 | 中（收割后留新钩子） |
| 爽点章 | 核心爽点兑现 | 中 |

## 二、网文节奏黄金法则（复用 batch-outliner 标准）

### 1. 爽点周期控制
- **打脸/冲突周期 ≤ 5章**（约12000字以内完成一个完整的"压迫→反击→收割"循环）
- **每章至少1个小爽点**（打脸、获宝、升级、秀操作、配角震惊、感情推进）
- **每3-5章一个大爽点**（跨阶打脸、群体震惊、反派跪下、势力臣服）
- 🔴 太长没爽点 = 掉读者，宁可压缩铺垫也要保证爽点密度

### 2. 压弹簧法则
- 压抑越久，爆发越爽：先制造困境/误解/打压 → 再极限反转
- 铺垫不超过2-3章，第3章必须开始反击
- 用细节放大屈辱感，让读者"憋着一口气"

### 3. 反差碾压法则
- 身份反差 / 实力反差 / 认知反差，用配角的反应放大爽感

### 4. 六步爽点结构（每个大爽点弧线参考）
1. 潜龙勿用（隐藏实力）→ 2. 见龙在田（初露锋芒）→ 3. 终日乾乾（持续拼搏）→ 4. 或跃在渊（形势危急）→ 5. 飞龙在天（全力爆发）→ 6. 亢龙有悔（收割+埋新伏笔）

### 5. 节奏波浪
- 高潮后必须插入 1-2章缓冲（日常/过渡/感情戏），让读者喘口气
- 缓冲章也要有小爽点
- 连续3章以上纯铺垫 → 🔴 大纲设计失败，必须调整

### 6. 新角色引入节奏（本书专属规则）
- 单场戏有名字角色 ≤ 4~5 个，其余用身份称呼
- 本章新引入命名角色 ≤ 2 个为宜（大纲明确要求除外）；开篇前 3 章新角色总量建议 3 个左右
- 贯穿配角不每章出场，3~5 章登场一次留期待
- 🔴 复用性判断：本章戏份少但后续剧情会复用的角色（线人、常驻店主、组织成员等）应命名建档而非 `~泛称~`

## 三、剧情设计模式（可复用冲突包）

**标准打脸包**（3-5章）：触发（挑衅/看不起/设局）→ 压迫升级 → 主角亮底牌（方式要新颖）→ 收割 → 伏笔
**探险寻宝包**（3-5章）：线索出现 → 进入险地 → 竞争者出现 → 获得宝物（付代价）→ 连锁反应
**势力征服包**（5-8章）：新势力登场 → 初次交锋 → 矛盾升级 → 主角全力出击 → 势力臣服/结盟 → 收割+敌反应
**感情推进包**（2-3章）：共同经历危险 → 独处时刻 → 误会/试探 → 关系确认

## 四、伏笔规划规则

- 每5章至少埋设 1 个新伏笔（📌）
- 伏笔回收周期：短线 5-15章，中线 20-50章，长线 50-100章
- 🔴 活跃伏笔不超过 8-10 个（太多读者记不住），新埋要考虑先回收旧的
- 新埋伏笔：`📌F-[章节号]-[序号]`（如 📌F-52-1）；回收：`✅F-[原埋设章节号]-[序号]`（如 ✅F-30-1）
- 🔴 回收时必须引用 `novel/state.yaml` 中 active 列表的实际 ID

## 五、卷结构规则

- 每卷 8-15章（约2-4万字）
- 每卷有独立的**核心矛盾**和**解决结果**，卷首有吸引力，卷尾有重大转折或悬念
- 上一卷末尾的伏笔/钩子 → 下一卷开头必须回应
- 角色状态/位置必须连续
- 节奏：上一卷高潮结束 → 下一卷开头可以先缓一缓再起新冲突
</outline_generation_rules>

<steps>
1) **分析当前剧情节点**：
   - 从 state.yaml + 近章摘要 获取：主角当前在做什么、目标是什么、面临什么困难
   - 从已有大纲的 `## 主线悬念` / `## 全书走向` 获取：大方向走势
   - 从活跃伏笔列表获取：哪些伏笔需要在近期回收
   - 从角色设定获取：哪些角色可以在后续登场/发展

2) **规划卷结构**：
   - 确定本次扩纲的章节范围需要几卷
   - 每卷设定**核心矛盾**（一句话）和**核心爽点**（最爽的场景）
   - 安排伏笔的埋设和回收节奏
   - 🔴 确保每卷有至少 2 个大爽点弧线

3) **生成逐章结构化章纲**：
   - 按卷逐章展开
   - 每章：一段式梗概（保持现有格式）+ 结构化字段（mode=structured 时）
   - 标注关键转折（🔥）、大高潮（⭐）
   - 标注伏笔埋设（📌）和回收（✅）
   - 🔴 检查爽点密度：连续3章无爽点 → 必须调整

4) **衔接检查**：
   - 新大纲第一章必须自然衔接上一章结尾
   - 活跃伏笔中预计本批次回收的 → 安排到合适位置
   - 角色出场/位置必须与 state.yaml 一致
   - 🔴 检查新角色引入节奏（单场 ≤5、本章新角色 ≤2、复用角色命名）

4.5) **检测大纲格式（格式自适应，关键兼容）**：
   - 🔴 **读取 `novel/outline.md` 已有章节的格式，必须沿用同一格式，不得混用**：
     - **标题式**（如 `### 第5章 标题` 或 `### 卷三：xxx` + `### 第N章`）：按标题式输出，结构化字段作为梗概后的缩进块
     - **表格式**（如 `| 章节 | 梗概 | 关键事件 | 伏笔 | 节奏 |` 表头 + `| 001 | ... |` 行）：🔴 按表格行输出，**每章追加一行 `| NNN | 梗概 | 关键事件 | 伏笔操作 | 节奏 |`**；结构化字段并入表格各列（功能定位写入节奏列，情节要点/爽点/钩子压缩进梗概或关键事件列），章末钩子并入伏笔列或关键事件列
   - 检测方法：在 `outline.md` 全文中搜索是否出现 `^\|` 开头的章节行（表格式）或 `^###\s+第N章`（标题式）；混用时以已规划章节的主体格式为准
   - 🔴 卷标题格式同步：表格式大纲的卷标题用 `### 卷X：标题（第N-M章）`，标题式用 `## 第X卷：标题（第N-M章）`，保持与已有卷标题一致

5) **写入 outline.md**：
   - 将新卷/章追加到 `novel/outline.md` 的卷章结构末尾
   - 🔴 **不覆盖已有章节**，只追加
   - 更新大纲头部的 `当前已规划` 范围（如 `当前已规划：第1—70章`）
   - 如"待续篇章"段的内容已被本次扩纲覆盖 → 更新或删除该段
   - 更新 `## 伏笔规划` 表格（如有新增伏笔）

6) **返回摘要给主流程**：
   ```
   扩纲完成:
   范围: 第X章 → 第Y章
   新增卷数: N
   新增章数: M
   模式: structured / standard
   新埋伏笔: [ID列表]
   预计回收: [ID列表及对应章节]
   关键爽点: [列出每卷最大爽点]
   新角色: [列出新登场命名角色，标注后续复用性]
   ```
</steps>

- 🔴 不修改 novel/constitution/ / novel/state.yaml / content.md / design.md / summary.md
