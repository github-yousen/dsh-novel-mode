<objective>
在独立上下文中，基于宪法设定 + 已有大纲 + 当前剧情进度 + 活跃伏笔 + 近章摘要，自动生成**指定范围**的逐章大纲梗概，追加到 `novel/outline.md` 末尾。

无需用户交互确认，直接生成最终版并写入文件。用于批量写作流程（/novel-batch）中自动补全缺失的大纲覆盖。

🔴🔴🔴 **每次调用只处理一个卷（≤20章）**：主流程按卷分批调用，每次传入一个卷的章节范围（如 `startChapter=52, endChapter=68`）。如果范围超过20章，只处理前20章并在返回摘要中标注。
</objective>

## 一、网文节奏黄金法则

🔴 **爽感密度是网文的生命线**。扩纲时必须遵守以下节奏规则：

### 1. 爽点周期控制
- **打脸/冲突周期 ≤ 5章**（约12000字以内完成一个完整的"压迫→反击→收割"循环）
- **每章至少1个小爽点**（可以是：打脸、获宝、升级、秀操作、配角震惊、感情推进）
- **每3-5章一个大爽点**（如：跨阶打脸、群体震惊、反派跪下、势力臣服）
- 🔴 太长没爽点 = 掉读者，宁可压缩铺垫也要保证爽点密度

### 2. 压弹簧法则
- **压抑越久，爆发越爽**：先制造困境/误解/打压 → 再极限反转
- 铺垫不超过2-3章，第3章必须开始反击
- 用细节放大屈辱感（配角嘲讽、群体鄙视），让读者"憋着一口气"
- 反转时要有**实际交锋过程**，不是一句话带过

### 3. 反差碾压法则
- **身份反差**：被看不起的人 → 其实是大佬
- **实力反差**：看似弱鸡 → 一出手惊天动地
- **认知反差**：别人费尽心机得不到的东西 → 主角轻松获得
- 用**配角的反应**（震惊/膜拜/后悔/嫉妒）放大爽感

### 4. 六步爽点结构（每个大爽点弧线参考）
1. **潜龙勿用**：主角低调登场/隐藏实力
2. **见龙在田**：初露锋芒，引起注意
3. **终日乾乾**：遭遇强敌/困难，持续拼搏
4. **或跃在渊**：形势危急，读者担心
5. **飞龙在天**：全力爆发，碾压对手（本弧线高潮）
6. **亢龙有悔**：收割战果 + 埋下新伏笔/新威胁

### 5. 节奏波浪
- 🔴 高潮后必须插入 1-2章缓冲（日常/过渡/感情戏），让读者喘口气
- 缓冲章也要有小爽点（如：获得奖励、感情升温、敌人听闻消息后的恐惧）
- 连续3章以上纯铺垫 → 🔴 **大纲设计失败，必须调整**

## 二、剧情设计模式

### 模块化冲突包（可复用的剧情单元）
每个"冲突包"包含完整的起承转合：

**标准打脸包**（3-5章）：
```
触发（有人挑衅/看不起/设局）
→ 压迫升级（更多人加入嘲笑/威胁升级）
→ 主角亮底牌（打脸方式要新颖，不能重复）
→ 收割（获得资源/声望/盟友/美人青睐）
→ 伏笔（新敌人闻讯/更大势力注意到）
```

**探险寻宝包**（3-5章）：
```
线索出现（传说/地图/情报）
→ 进入险地（环境描写+小怪清扫）
→ 竞争者出现（抢夺/背叛/三方混战）
→ 获得宝物（但付出代价/触发机关）
→ 连锁反应（宝物引发新事件/升级/暴露位置）
```

**势力征服包**（5-8章）：
```
新势力登场（展示其强大/傲慢/与主角的利益冲突）
→ 初次交锋（主角小试牛刀，对方不服）
→ 矛盾升级（对方召集更强力量/设局）
→ 主角全力出击（核心对决，场面要大）
→ 势力臣服/结盟（条件要有趣/搞笑/出人意料）
→ 收割战利品 + 敌方内部反应
```

**感情推进包**（穿插在主线中，2-3章一段）：
```
共同经历危险（战斗中互相保护/配合）
→ 独处时刻（日常互动/心理活动）
→ 误会或试探（第三者介入/性格碰撞）
→ 关系进一步确认（告白/道誓/肢体接触升级）
```

### 地图升级模式
- 每个新地图/新势力 = 一个新的挑战循环
- 新地图的规则/禁忌/强者 要与主角能力形成**有趣的冲突**
- 不同地图的打脸方式要有**差异化**（不能每次都一样的套路）

## 三、伏笔规划规则

### 伏笔密度
- 每5章至少埋设 1 个新伏笔（📌）
- 伏笔回收周期：短线 5-15章，中线 20-50章，长线 50-100章
- 🔴 活跃伏笔不超过 8-10 个（太多读者记不住），新埋要考虑先回收旧的

### 伏笔类型
- **物品伏笔**：看似平凡的物品，后来起关键作用
- **人物伏笔**：某角色的隐藏身份/秘密/过去
- **场景伏笔**：某地的异常细节，后来成为重要线索
- **对话伏笔**：某句看似无意的话，后来一语成谶
- **反转伏笔**：刻意引导错误预期，后来大反转

### 伏笔格式
- 新埋伏笔：`📌F-[章节号]-[序号]`（如 📌F-52-1）
- 回收伏笔：`✅F-[原埋设章节号]-[序号]`（如 ✅F-30-1）
- 🔴 回收时必须引用 `novel/state.yaml` 中 active 列表的实际 ID

## 四、卷结构规则

### 卷划分
- 每卷 8-15章（约2-4万字）
- 每卷有独立的**核心矛盾**和**解决结果**
- 卷首必须有吸引力（新地图/新危机/新角色），卷尾必须有**重大转折或悬念**

### 卷间衔接
- 上一卷末尾的伏笔/钩子 → 下一卷开头必须回应
- 角色状态/位置必须连续
- 节奏：上一卷高潮结束 → 下一卷开头可以先缓一缓再起新冲突

<steps>
1) **分析当前剧情节点**：
   - 从 state.yaml + 近章摘要 获取：主角当前在做什么、目标是什么、面临什么困难
   - 从已有大纲的 `## 主线悬念` / `## 全书走向` 获取：大方向走势
   - 从活跃伏笔列表获取：哪些伏笔需要在近期回收
   - 从角色设定获取：哪些角色可以在后续登场/发展

2) **规划卷结构**：
   - 确定本次扩纲的章节范围需要几卷
   - 每卷设定**核心矛盾**（一句话）和**核心爽点**（最爽的一个场景是什么）
   - 安排伏笔的埋设和回收节奏
   - 🔴 确保每卷有至少 2 个大爽点弧线

3) **生成逐章梗概**：
   - 按卷逐章展开，生成每章梗概
   - 标注关键转折（🔥）、大高潮（⭐）
   - 标注伏笔埋设（📌）和回收（✅）
   - 🔴 检查爽点密度：连续3章无爽点 → 必须调整

4) **衔接检查**：
   - 新大纲第一章必须自然衔接上一章结尾
   - 活跃伏笔中预计本批次回收的 → 安排到合适位置
   - 角色出场/位置必须与 state.yaml 一致
   - 如已有大纲存在"待续篇章"/"主线悬念"段 → 参考但不照搬，可以在此基础上创新

5) **写入 outline.md**：
   - 将新卷/章追加到 `novel/outline.md` 的卷章结构末尾
   - 🔴 **不覆盖已有章节**，只追加
   - 更新大纲头部的 `当前已规划` 范围
   - 如"待续篇章"段的内容已被本次扩纲覆盖 → 更新或删除该段
   - 更新 `## 伏笔规划` 表格（如有新增伏笔）

6) **返回摘要给主流程**：
   ```
   扩纲完成:
   范围: 第X章 → 第Y章
   新增卷数: N
   新增章数: M
   新埋伏笔: [ID列表]
   预计回收: [ID列表及对应章节]
   关键爽点: [列出每卷最大爽点]
   ```
</steps>

<constraints>
- 🔴🔴🔴 **每次调用处理不超过20章**，超出则只处理前20章
- 🔴 不与用户交互，不展示草稿等确认，直接生成最终版
- 🔴 不修改 novel/constitution/ / novel/state.yaml / content.md / design.md / summary.md
- 🔴 只修改 `novel/outline.md`（追加内容，不覆盖已有章节）
- 🔴 章节梗概必须**具体到事件**（"主角击败张三获得宝剑"），禁止模糊笼统（"主角继续冒险"）
- 🔴 伏笔ID格式：`F-[章节号]-[序号]`，新埋伏笔的章节号必须是实际安排埋设的章节号
- 🔴 生成的大纲必须符合 `novel/constitution/core.md` 中的世界观规则，并遵守 `novel/outline.md` 头部「创作约束」中的审核红线和避毒指南
- 🔴 **爽点密度自检**：生成完毕后扫一遍，如发现连续3章以上无爽点/冲突 → 必须调整后再写入
- 发现设定疑问 → 在返回摘要中标注，不自行决定
</constraints>
