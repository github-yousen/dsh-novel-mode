# novel-disassemble

## 用户输入

```text
$ARGUMENTS
```

用户输入为源书稿的路径、文件说明或**番茄小说URL/ID**。支持参数：
- 路径 — 源书稿文件/目录
- 番茄小说URL — `https://fanqienovel.com/page/xxxx`（自动下载）
- 番茄小说ID — 纯数字ID如 `7143038691944959011`（自动下载）
- `--genre [类型]` — 目标新书类型（如 `都市` `玄幻` `科幻`，默认同源书）
- `--depth [粗拆|精拆]` — 拆解深度（默认 `精拆`）
- `--chapters [N]` — 只下载/分析前N章（默认30，推荐先拆前30章）
- `--skip-write` — 只输出拆书报告，不执行换皮重构

🔴 **当输入为番茄小说URL/ID时**，自动执行 Phase 0 下载源书。

## 目标

**"换骨不换皮"的工业化流程**：从一本热门书籍中提取底层骨架（主线结构、节奏模式、钩子编排、爽点公式、人设模板、金手指设计、文笔风格），然后用全新的世界观+人设+设定**彻底换皮**重构为一本原创小说，最终产出标准的 `novel/constitution/` + `novel/outline.md`，直接接入现有写作流程。

🔴 **反抄袭铁律**：
- 骨架可复用（结构、节奏、技巧模式），但**具体剧情、场景、对话、设定一律不得复制**
- 输出的新大纲中，每个章节梗概必须与源书**无任何内容层面的雷同**
- 角色只继承"功能定位"（导师型、宿敌型、红颜型），不继承姓名/外貌/台词/身世
- 世界观必须从零设计或从用户指定类型的预设库生成

## 上下文管理原则

🔴 **与 `/novel-import` 同架构：主流程始终轻量，重活交 SubAgent**
```
主流程上下文 ≈ 调度逻辑 + 文件名列表 + 拆解报告摘要 (< 2000字)
├── SubAgent book-analyzer: 分批拆解源书 (每批≤5章，独立会话，含文笔风格分析)
├── SubAgent skeleton-rebuilder: 骨架换皮重构 (独立会话)
└── 脚本: 进程外统计分析 (0上下文)
```

## Phase 0: 自动下载番茄源书（条件执行）

🔴 **仅当用户输入为番茄小说URL或纯数字ID时执行此阶段**。如输入已是本地路径则跳过。

**识别规则**：
- 包含 `fanqienovel.com` → 提取URL中的数字ID
- 纯数字且 ≥ 10位 → 视为番茄小说ID
- 其他 → 视为本地路径，跳过 Phase 0

```bash
python3 .dsh/scripts/fanqie-download.py <book_id> --output-dir "novel/source" --chapters <N>
```

🔴 `--chapters` 默认30，可由用户通过 `--chapters` 参数覆盖。

下载完成后，向用户展示：
```
━━━ 📖 源书下载完成 ━━━

书名: 《xxx》
作者: xxx
已下载: 前30章（成功XX/失败XX）
存储位置: novel/source/

继续拆书分析？回复"确认"或"取消"。
```

确认后，将 `novel/source` 作为源书路径传入 Phase 1。

## Phase 2: 数值化预分析（脚本，进程外）

```powershell
pwsh -File .dsh/scripts/analyze-source.ps1 -InputDir "novel/source/chapters"
```

脚本在进程外计算（不占主会话上下文）：

**a) 基础统计**
- 总章数、总字数、平均章节字数
- 字数波动曲线（标记异常短/长的章节 → 可能是高潮或过渡）

**b) 节奏指纹**
- 每章字数绘制成曲线，自动标记波峰（高潮章）和波谷（过渡章）
- 计算"爽点周期"：相邻波峰间隔平均章数
- 高潮章占比

**c) 对话/叙事比**
- 每章对话占比，全书对话均值
- 对话密度变化趋势（前期 vs 后期）

**d) 钩子密度估算**
- 统计每章末尾段（最后200字）的悬念关键词频率（"突然"/"竟然"/"但是"/"却"/"谁知"/"一个声音"/"不对"等）
- 估算钩子强度曲线

**e) 情绪词频分析**
- 统计打斗词/甜蜜词/紧张词/搞笑词/悲伤词频率
- 输出情绪分布图（标记全书情绪走向）

**f) 卷结构识别**
- 按字数+情绪曲线的大波谷自动划分"逻辑卷"
- 输出建议分卷方案

脚本输出 `novel/source/analysis.json`（结构化数据）+ `novel/source/analysis-summary.txt`（人类可读摘要，~500字）

主流程**只读 summary 文件**，展示给用户。

## Phase 3: 七维深度拆解（SubAgent × N轮）

🔴 **每5章一批，调用 SubAgent `book-analyzer`**，按拆书七大维度提取骨架：

```
每5章一批，调用 SubAgent book-analyzer：
├── 第1轮: 读第1-5章 + analysis.json 中本批数据 → 输出 dissect-001.yaml
├── 第2轮: 读第6-10章 + dissect-001.yaml → 输出 dissect-002.yaml
├── ...
└── 第N轮: 最后几章 → dissect-N.yaml
```

每轮 SubAgent 在独立上下文中提取：

### 维度1: 主线框架
- 本批的阶段性目标（主角这5章在达成什么小目标）
- 阶段间的推进逻辑（地图切换/敌人升级/谜题解锁/关系变化）
- 与上一批的因果链

### 维度2: 节奏控制
- 本批中的爽点位置（具体章节号 + 类型：打脸/升级/揭秘/获宝）
- 情绪曲线走向（铺垫→上升→高潮→回落）
- 张弛节奏标注

### 维度3: 钩子设置
- 本批中每章末尾钩子的类型和手法
- 伏笔埋设位置 + 内容摘要（不复制原文，只归纳手法）
- 伏笔回收位置
- 钩子有效性评估（1-5星）

### 维度4: 人设塑造
- 本批出场角色的**功能定位**（导师/宿敌/红颜/跟班/路人甲）
- 角色行为模式标签（沉默行动派/嘴炮智谋型/热血冲动型...）
- 角色关系变化（冲突/合作/暧昧/背叛...）
- 反差点（外表 vs 内心，口头 vs 行动）

### 维度5: 金手指/核心设定
- 金手指的使用频率和场景
- 限制条件和代价
- 升级节奏

### 维度6: 爽点/情绪点
- 本批中爽点的构成公式：`压抑积累(X章) + 爆发释放 + 情绪放大(技巧)`
- 爽点四要素覆盖：①掌控感 ②反差爆破 ③他人认同 ④破坏欲
- 具体技巧手法归纳（不复制原文内容）

### 维度7: 文笔风格深度分析
- 句式节奏：不同场景下的句子长短搭配习惯
- 描写偏好：动作/心理/环境/外貌的风格和权重
- 对话风格：密度、单句长度、标记习惯、角色区分度
- 叙事手法：人称视角、信息释放策略、时间线处理
- 情绪渲染方式：如何传达情绪、高潮渲染技巧
- 语言调性：口语化程度、幽默方式、语域切换
- 风格变化：本批与前批相比的文笔演变
- 🔴 **全部用人话自主总结**，输出写作AI能直接理解和模仿的风格描述，不要只给数值

🔴 **SubAgent 输出规则**：
- 只输出结构性分析（模式/手法/节奏），**禁止摘抄/引用原文段落**
- 角色只记录"功能标签"，不记录姓名/具体身世
- 剧情只记录"事件类型"（被陷害→翻盘→升级），不记录具体情节
- 文笔风格分析用自然语言描述，不输出干巴巴的统计数值
- 输出格式为 `novel/source/dissect-[batch_id].yaml`（含 `style_fingerprint` 字段）

## Phase 4: 合并拆书报告（主流程）

读取所有 `novel/source/dissect-*.yaml`（每个几百字），合并生成**拆书总报告**。

读取模板 `.dsh/templates/disassemble-report.md`，生成 `novel/source/report.md`：

```
=== 拆书报告 ===

### 主线结构
- 总章数: 186章，分3段（起步期/扩张期/决战期）
- 阶段推进模式: 地图升级型（每段切换一个更大的舞台）
- 核心冲突升级路径: 个人恩怨 → 势力对抗 → 世界级危机

### 节奏模式
- 爽点周期: 平均每4.2章一个小爽点
- 高潮周期: 平均每15章一个段落高潮
- 张弛比: 3:1（3章紧张 + 1章缓和）
- 情绪曲线类型: 波浪上升型

### 钩子编排
- 钩子类型分布: 危机预警40% / 未解之谜25% / 意外事件20% / 暗示15%
```

## Phase 5: 引导换皮设定（主流程交互）

基于拆书报告，引导用户为**新书**选择设定。

### 🚀 快捷模式（用户回复"全自动"或"默认"触发）

🔴 **用户在 Phase 5 任何位置回复"全自动"/"默认"/"快速"，立即跳过所有引导步骤**，Agent 根据拆书报告自动决策全部设定：

| 设定项 | 自动决策规则 |
|:------|:-----------|
| 目标类型 | 同类型换皮（与源书相同类型） |
| 金手指 | 同类型但不同表现（Agent 自动创造新金手指，保留功能模式） |
| 主角起点 | 保持相似起点模式 |
| 冲突升级路径 | 保持类似升级路径 |
| 角色映射 | Agent 根据源书角色功能矩阵自动生成全新角色（新姓名/新性格/新说话风格） |
| 目标规模 | 与源书相近章数，分段规划（先规划前50章） |
| 文笔风格 | 继承源书风格指纹 |

自动决策完成后，**直接展示 Step 4 确认总览**（一次性展示所有自动决策结果），用户只需一次"确认"即可进入 Phase 6。

🔴 如用户对自动结果不满意，可在总览中回复修改项编号逐项调整，无需从头走引导流程。

---

### 常规模式（逐步引导）

### Step 1: 目标类型

```
源书类型: [源书类型]
你想写什么类型的新书？

A) 同类型换皮 — 保持相同类型，换全新设定
B) 跨类型移植 — 把骨架移植到另一类型
   [展示类型列表: 玄幻/都市/科幻/古代/悬疑/奇幻/末日/校园]
C) 自定义 — 我来描述

选择类型后，Agent 自动从 /novel-constitution 的类型预设库加载默认世界观。
```

### Step 2: 核心差异化

```
源书的核心卖点是: [从拆书报告提取]
你的新书需要与源书形成差异化。请选择或自定义：

【金手指变换】源书金手指模式: [抽象描述]
A) 同类型但不同表现 — 例: 源书是"系统"，你用"传承记忆"
B) 完全不同类型 — 例: 源书是"系统"，你用"时间回溯"
C) 自定义

【主角起点变换】源书起点: [抽象描述，如"废柴逆袭"]
A) 保持相似起点模式
B) 反转起点 — 例: 源书从底层开始，新书从顶层跌落
C) 自定义

【冲突升级路径变换】源书路径: [如"个人→势力→世界"]

```

## Phase 6: 骨架重构（SubAgent）

用户确认后，调用 SubAgent `skeleton-rebuilder`，传入：
- 拆书报告 `novel/source/report.md`
- 用户确认的换皮设定（含 `target_chapters`、`plan_range`、`plan_mode`）
- 类型预设模板

SubAgent 在**独立上下文**中生成：

### a) 新宪法

按 `/novel-constitution` 标准结构输出：
- `novel/constitution/core.md` — 全新世界观（基于用户选择的类型+自定义）
- `novel/constitution/style.md` — 可参考源书风格指纹调整，但必须有差异
- `novel/constitution/characters/[角色名].md` — 每个角色一个文件

### b) 新大纲

**关键：骨架映射规则**

以源书骨架DNA为蓝本，但内容全部换新：

| 源书骨架元素 | 新书映射方式 |
|-------------|-------------|
| 阶段划分(X段Y章) | 保留相似的章节分配比例 |
| 爽点周期(每N章) | 保留相同节奏密度 |
| 钩子类型分布(40%/25%/...) | 保留类似分布比例 |
| 爽点公式(被轻视→反转→震惊) | 保留公式骨架，填入全新场景 |
| 情绪曲线(波浪上升型) | 保留曲线形态 |
| 角色出场时序 | 保留类似的出场节奏 |

🔴 **映射禁区**：
- 禁止复制任何具体剧情事件
- 禁止复制角色的具体经历/身世/对话
- 禁止复制地名/组织名/功法名/道具名
- 新大纲每章梗概必须是全新创作的场景

输出标准 `novel/outline.md`（格式与 `/novel-design all` 一致）

### c) 初始化状态

```powershell
# 生成初始 state.yaml（空白初始状态）
```

写入空白 `novel/state.yaml`（从模板生成）

## Phase 7: 反抄袭校验（脚本 + 主流程）

🔴 **双重校验，确保"换骨不换皮"**：

### 7a. 脚本级文本相似度检测

```powershell
pwsh -File .dsh/scripts/analyze-source.ps1 -Mode similarity -SourceDir "novel/source/chapters" -TargetFile "novel/outline.md"
```

检测项：
- 新大纲与源书正文的 N-gram 重叠率（阈值 < 15%）
- 新角色名是否在源书中出现过（必须为 0）
- 新地名/组织名是否在源书中出现过（必须为 0）

### 7b. AI语义级查重

主流程读取新大纲（~2000字）和拆书报告（~1500字），进行语义对比：
- 检查每章梗概是否只是源书对应章节的"同义替换"
- 标记相似度高的章节，提示用户重新设计

```
=== 反抄袭校验 ===

✓ 文本重叠率: 3.2% (阈值<15%, 通过)
✓ 角色名检测: 0个重叠 (通过)
✓ 地名检测: 0个重叠 (通过)
⚠ 语义相似: 第12章梗概与源书第15章结构过于相似，建议调整

需要修改标记的章节吗？回复章节号修改，或"跳过"继续。
```

## 源书数据隔离

🔴 **源书文件全部存放在 `novel/source/` 目录，与正式创作目录完全隔离**：

```
novel/
├── source/                    ← 源书数据（只在拆书阶段使用）
│   ├── chapters/              ← 源书拆分后的章节
│   │   ├── 001/content.md
│   │   └── .../
│   ├── analysis.json          ← 数值分析结果
│   ├── analysis-summary.txt   ← 分析摘要
│   ├── dissect-001.yaml       ← 分批拆解输出
│   ├── dissect-002.yaml
│   ├── ...
│   └── report.md              ← 拆书总报告
├── constitution/              ← 新书宪法（全新设定）
├── chapters/                  ← 新书章节
├── outline.md                 ← 新书大纲
└── state.yaml                 ← 新书状态
```

🔴 **后续 `/novel-write` `/novel-design` `/novel-validate` 的所有 Agent 和脚本，禁止读取 `novel/source/` 目录下的任何文件**。这确保写作过程不可能"参考"源书原文。

## 约束

- 🔴 **反抄袭铁律**：新书的任何正文/设定/角色/地名不得与源书有直接对应关系
- 🔴 拆书报告只记录"结构模式"和"技巧手法"，**禁止摘抄/引用源书原文**
- 🔴 SubAgent `book-analyzer` 输出中禁止出现源书角色真名、地名、功法名等具体名词
- 🔴 源书数据隔离在 `novel/source/`，写作阶段不可访问
- 🔴 新大纲必须通过反抄袭校验才能进入写作流程
- 🔴 骨架复用仅限：节奏模式、结构比例、技巧公式、角色功能定位、文笔风格特征
- 🔴 用户在 Phase 5 的每一步都可以"跳过"，Agent 用合理默认值填充
- 🔴 主流程禁止读取源书正文，正文只由 SubAgent 在独立会话中读取
