# novel-design

## 用户输入

```text
$ARGUMENTS
```

执行前必须考虑用户输入（如非空）。支持三种模式：
- `all` — 创建/编辑全书大纲
- `all --extend` — 追加大纲（从已有大纲末尾续接新章节/新卷）
- `N` — 创建第N章的设计稿

可选参数（模式 `N`）：
- `N` — 默认执行双重校验：脚本校验（validate-design.ps1）+ SubAgent `continuity-validator`（stage=design）语义校验
- `N --deep` — 历史兼容参数（已与默认行为一致：默认即含语义校验），保留仅防旧脚本调用

示例：
```
/novel-design 5
/novel-design 5 --deep
```

## 前置检查

- [ ] 读取 `novel/state.yaml`（如存在）

## 模式A：大纲设计（all）

### 1. 检查现有大纲

- 检查 `novel/outline.md` 是否存在
  - 存在 → 询问：修改 / 重做 / 追加（等同于 `all --extend`）
  - 不存在 → 步骤2

### 2. 引导收集大纲信息

🔴 **不要求用户一次写完所有内容**，分步引导 + Agent 生成：

#### Step 1: 篇幅规划

```
先确定整体规模：

【预计总篇幅】（最终目标，可后续调整）:
A) 短篇 — 约 20-40 章（8-12万字，单线剧情，节奏紧凑）
B) 中篇 — 约 60-100 章（20-30万字，1-2条支线）
C) 长篇 — 约 150-300 章（50-100万字，多支线多卷）
D) 超长篇 — 约 300-1000 章（100万字+，多世界/多阶段）
E) 自定义（输入具体章数）

【本次规划范围】（重要！不一定要一次规划完）:
A) 全部规划 — 一次性设计到结局
B) 分段规划 — 先详细设计前N章，后续写完再追加
   例：总书约500章，先设计前100章
   💡 适合长篇连载：先写一批看成绩，再决定后续走向

【分卷结构】:
A) 不分卷 — 一路写到底
B) 分卷 — 请说明几卷、每卷大致主题
   例：第一卷·入门、第二卷·历练、第三卷·大战
```

🔴 **分段规划说明**：
- 用户选择"分段规划"时，需明确**本次规划的章节范围**（如"先设计前100章"）
- 大纲头部会记录 `预计总章数`（大目标）和 `当前已规划章数`（实际已设计的范围）
- 后续写完当前范围后，可通过 `/novel-design all --extend` 追加下一批大纲
- 🔴 即使是分段规划，也必须在 Step 2 中完成**全书主线走向**的粗略规划（3-5句话），确保后续追加时方向一致

#### Step 2: 剧情三要素

```
用简短的话描述（每项1-3句就够，Agent会帮你展开）：

1. 【开局】主角的初始处境 + 第一个冲突/契机
   例："废柴少年被逐出家族，意外获得上古传承"

2. 【中盘转折】故事最大的危机或反转
   例："发现师门隐藏的惊天阴谋，被迫叛出宗门"

3. 【结局走向】:
   A) 大团圆 — 主角达成目标，皆大欢喜
   B) 悲剧 — 代价惨重，虽胜犹败
   C) 开放式 — 留有余韵，不完全交代
   D) 反转式 — 最后一刻颠覆认知
   E) 自定义（请描述）
```

#### Step 3: 节奏偏好（可选）

```
你偏好的节奏模式？（可跳过，Agent会根据类型自动选择）

A) 稳步上升型 — 持续升级打怪，爽感递增
B) 波浪起伏型 — 高潮低谷交替，张弛有度
C) 慢热爆发型 — 前期大量铺垫，后期集中爆发
D) 悬念驱动型 — 每章留钩子，环环相扣
E) 自定义
```

#### Step 4: 关键支线/要素（可选）

```
有想好的支线或关键要素吗？（没有可跳过，Agent会根据类型建议）

例：
- 感情线：主角和苏晚的关系发展
- 势力线：三大宗门的权力博弈
- 秘密线：主角的身世之谜

直接描述，或回复"跳过"。
```

### 3. Agent 生成大纲草稿

🔴 **Agent 基于以上信息 + 宪法设定，自动生成完整大纲**，而不是让用户自己写：

- 读取 `novel/constitution/core.md` — 世界观规则
- 读取 `novel/constitution/style.md` — 风格偏好
- 🔴 生成 `novel/outline.md` 时，**必须先写头部 `## 创作约束` 段**（平台审核红线 + 本书避毒指南 + 豁免项）；后续 `batch-designer` / `novel-writer` / `continuity-validator` 都以此段为权威来源



#### 大纲生成策略（按总章数分级）

🔴 **短篇（≤50章）**：一次性生成全部大纲

🔴 **中长篇（>50章）且全部规划**：按卷分批生成，确保每卷质量
1. **第一步：生成全书卷结构**（~500字）
   - 每卷概要（卷名 + 核心冲突 + 章节范围 + 主要角色弧线）
   - 卷与卷之间的承接关系
   - 全书伏笔规划总览（哪些伏笔跨卷）
   - 展示给用户确认卷结构

2. **第二步：逐卷展开详细章节梗概**
   - 每卷独立生成，加载前一卷**末尾3章梗概**作衔接上下文
   - 每卷生成后展示给用户确认，确认后再继续下一卷
   - 🔴 每卷生成时必须参照全书卷结构中的承接关系，确保跨卷剧情连贯
   - 🔴 跨卷伏笔必须在对应卷的梗概中明确标注埋设/回收

3. **用户可以**：
   - 确认当前卷后自动进入下一卷
   - 修改当前卷的某些章节后再确认
   - 回退到上一卷修改（会级联更新后续卷的衔接部分）

🔴 **分段规划模式**（用户在 Step 1 选择了"分段规划"）：
1. **第一步：生成全书走向概要**（~300字，必须完成）
   - 全书主线走向（3-5句话，粗略描述起-承-转-合）
   - 大致分几个阶段/arc（如：起步期→扩张期→决战期）
   - 每个阶段的核心矛盾（一句话）
   - 🔴 这是后续追加大纲的"北极星"，确保不偏航
   - 写入 `novel/outline.md` 的 `## 全书走向（粗纲）` 段

2. **第二步：详细设计本次规划范围的卷/章**
   - 按中长篇逐卷生成的方式，只展开本次规划范围内的卷
   - 本次范围最后一卷的末尾，预留**过渡钩子**（衔接后续未规划部分）
   - 🔴 大纲末尾标注"待追加"分割线：
     ```
     --- ✂️ 以上为已规划范围（第1-100章）| 后续通过 /novel-design all --extend 追加 ---
     ```

3. **大纲头部记录规划元数据**：
   ```
   **预计总章数**: 500（大目标，可调整）
   **当前已规划**: 第1-100章
   **规划模式**: 分段规划
   ```

生成内容包括：
- 每章一行梗概（50字以内）
- 标注关键转折章节（🔥）
- 标注高潮节点（⭐）
- 标注伏笔埋设（📌）/ 回收（✅）计划
- 节奏标注：铺垫 / 上升 / 高潮 / 过渡

🔴 **节奏与爽点规则**（Agent 生成大纲时必须遵守）：
- 前3章必须完成：主角出场（第1章第1段）→ 金手指亮相 → 首次打脸，节奏要快
- 打脸/冲突周期 ≤ 5章完成（11000-14000字），太长会掉读者
- 高潮后插入1-2章日常/过渡缓冲，放松读者情绪
- 爽点四要素须交替覆盖：①秩序与掌控感（稳步变强）②反差爆破（扮猪吃老虎）③他人反应的认同（配角震惊）④破坏欲释放（癫狂剧情）
- 第一卷（前10万字）节奏最快，1章2-3场景，避免拖沓

🔴 **写长不崩法则**（长篇大纲策略，Agent 规划大纲时自动应用）：
> 流水不争先，争的是滔滔不绝。—— 起点编辑星河

- **卖点分阶段演变**（最高级的技巧）：
  - 前几万字（上架前）：简单装逼、收获的爽感为主，快速建立读者期待
  - 20万字上架后：换卖点 — 地位提升、身份特殊、收获大佬人情，防止爽感同质化
  - 百万字以上：世界观揭秘，多条暗线收缩汇总，给长期读者交代
- **扮猪吃老虎是永远的套路**：主角外在不能太顺利，学会藏实力 — 只有读者知道，其他人不知道。主角过早太爽、接触层次太高，崩盘即将开始
- **多挖坑、多埋线**：多设支线（创业+文娱+恋爱、玄幻+悬疑+探险混合），走主线时浑然天成地圆回来，避免干巴巴的单一叙事
- **藏拙，不全把精华前置**：开头读者预设不能拉太高。多钩子、多伏笔，比直接正反馈拉满好得多
- **重视人设和配角**：人设立住了，不管故事怎么发展读者都舍不得弃书。配角必须活灵活现（兄弟、伙伴、知己、有深度的反派、绝代大佬）
- **心态**：不焦虑一时数据，理性面对读者批评和成绩波动。写书是长期过程

🔴 展示格式采用**结构化章节级规划**，目标是让用户看到的草稿清晰、可定位、便于后续设计与校验直接阅读：

```
=== 大纲草稿 ===

**书名**: [X]
**预计总章数**: [X]
**当前已规划**: 第1-XX章
**规划模式**: [全部规划/分段规划]
**类型/标签**: [X]

## 创作约束
- 【死线】[平台审核红线；不可删除的绝对禁区]
- 【黄线】[可涉及但必须技巧处理的内容]
- 【弹性区】[可写但须控制尺度的内容]
- 【本书避毒指南】[该书特有的禁写项 / 审美避坑]
- 【豁免项】[如历史架空需保留真实朝代名等，未配置则写"无"]

## 全书走向（粗纲）
[3-5句话概述主线走向]

### 阶段划分
- 阶段一（第1-XX章）：[核心矛盾]
- 阶段二（第XX-XX章）：[核心矛盾]
- ...

## 主线剧情
[3-5句话概述]

## 卷章结构

### 第一卷: [卷名]（第1-15章）

**本卷目标**: [核心冲突]

| 章节 | 梗概（50字内） | 关键事件 | 伏笔操作 | 节奏 |
|------|--------------|---------|---------|------|
| 1 | [梗概] | | | 铺垫 |
| 2 | [梗概] | | 📌F-2-1 身世之谜 | 铺垫 |

| ... | | | | |

### 第二卷: [卷名]（第16-30章）
```

🔴 用户可以：
- 回复 `确认` → 直接采用
- 回复 `第5章改成XXX` → Agent 修改对应章节
- 回复 `第一卷太短了，扩展到20章` → Agent 调整
- 回复 `加一条感情线` → Agent 在合适位置插入

### 4. 写入大纲

确认后写入 `novel/outline.md`

### 4.5 大纲可读性自检

执行人工/Agent 自检：
- `outline.md` 头部存在可直接读取的 `## 创作约束` 段，且死线 / 黄线 / 弹性区 / 本书避毒指南 / 豁免项信息完整
- `outline.md` 全文中能**明确定位到章节级规划**
- 当前大纲保留了足够的信息，供后续 `batch-designer` / `novel-writer` / `continuity-validator` 直接从**全文**理解本章目标、事件、约束与衔接关系


如发现章节信息模糊、断档或无法定位，再回到本步骤继续修正；无需因为"不是 5 列表格"而阻断。

### 4.6 大纲语义评审（continuity-validator，stage=outline）

🔴 大纲除结构自检外，必须再经 `continuity-validator` 语义评审（与批量模式 Step O1 对齐，检查全书方向 / 实际衔接 / 节奏 / 角色 / 资源 / 伏笔链）：

调用 SubAgent `continuity-validator`，使用 `stage=outline`（rangeStart/rangeEnd = 本次规划范围，如 1-100）：

```
执行大纲连续性评审。
stage: outline
rangeStart: {本次规划起始章}
rangeEnd: {本次规划结束章}
请严格按照你的 <context_loading> 规则自行加载所有必要上下文。
```

结果处理：
- **PASS / observe-only WARNING** → 写入完成，进入步骤5
- **CRITICAL / ERROR** → 主会话对照大纲、state.yaml、前文事实独立核验（误报驳回并记录理由，漏报补入），确认后按报告做**最小回修**（只改问题章节，不整篇重写、不擅自改变全书方向）→ 再次调用 validator 复核，循环直到非 CRITICAL
- 无法安全判断 → 标记 `manual-review`，展示问题等待用户决策，不自动修改

```
大纲已创建（XX章）。下一步：
- 设计具体章节：/novel-design 1
- 直接写第一章：/novel-write 1
- 调整大纲：/novel-design all
- 追加后续大纲：/novel-design all --extend（分段规划模式下）
```

## 模式C：追加大纲（all --extend）

🔴 **适用场景**：用户之前使用分段规划，已写完当前范围，需要追加后续章节的大纲。

> 💡 **提示**：若希望扩纲采用**结构化章纲**（功能定位/情节要点/冲突/爽点/章末钩子/角色出场，按网文方法论），优先使用 `/novel-outline`（调用 SubAgent `chapter-outliner`）。本模式为快速一段式扩纲（主流程直接生成）。

### 1. 加载上下文

- 读取 `novel/outline.md` — 获取全书走向粗纲 + 已有大纲的末尾5章梗概
- 读取 `novel/constitution/core.md` + `style.md`
- 读取 `novel/state.yaml` — 获取当前写作进度、角色状态、活跃伏笔
- 读取已有大纲最后一卷末尾5章的 `summary.md`（如已写完，获取实际剧情走向）

### 2. 引导收集追加信息

```
━━━ 追加大纲 ━━━

当前大纲: 第1-100章（已规划）
全书目标: 约500章

已写到: 第XX章（来自 state.yaml）

【本次追加范围】: 从第101章到第___章
  例: 101-200（再追加100章）

【剧情走向调整】（可选）:
  写完前100章后，对剧情走向有新想法吗？
  A) 按原定全书走向继续
  B) 我想调整方向（请描述）

【新增要素】（可选）:
  需要引入新角色/新势力/新支线吗？
  直接描述，或回复"跳过"。
```

### 3. Agent 生成追加大纲

- 参照 `## 全书走向（粗纲）` 确保方向一致
- 读取已有大纲末尾章节梗概，确保剧情衔接
- 参照已有活跃伏笔，安排回收/新埋
- 按中长篇逐卷生成的方式展开新章节

🔴 **追加规则**：
- 新章节**追加到**已有大纲末尾，不覆盖已有章节
- **不得删除或改空**头部 `## 创作约束` 段；如发现缺失，必须先补齐后再追加正文规划
- 更新大纲头部的 `当前已规划` 范围（如 `第1-200章`）
- 更新"待追加"分割线位置（如有后续则保留，如已到结局则删除）
- 如果用户调整了剧情走向，同步更新 `## 全书走向（粗纲）` 段
- 🔴 新旧衔接处（第100-101章之间）必须检查伏笔连续性和剧情逻辑


### 4. 用户确认 & 写入

同模式A的确认流程，确认后追加到 `novel/outline.md`

### 4.5 追加后自检

执行追加后自检：
- 新追加章节在 `outline.md` 全文中都能被明确定位
- 新旧衔接处（如第100→101章）能从全文直接读出承接关系
- 追加内容保持全文阅读顺畅、结构清晰

### 4.6 追加后语义评审（continuity-validator，stage=outline）

🔴 追加内容除结构自检外，必须再经 `continuity-validator` 语义评审（与批量模式 Step O1 对齐；重点检查新旧衔接处伏笔连续性、全书方向一致性、逐章可执行性）：

调用 SubAgent `continuity-validator`，使用 `stage=outline`（rangeStart/rangeEnd = 本次追加范围，如 101-200）：

```
执行大纲连续性评审。
stage: outline
rangeStart: {本次追加起始章}

请严格按照你的 <context_loading> 规则自行加载所有必要上下文。
```

填充内容参照（设计稿应包含的要素，与模板骨架对应）：

读取模板 `.dsh/templates/chapter-design.md`，生成包含：

**a) 上文状态**（从 state.yaml 自动填充）
- 当前时间线位置
- 各角色当前位置/状态
- 本章需回收的活跃伏笔

**b) 本章目标**（从 outline.md 对应章节展开）
- 主线推进内容
- 伏笔操作：回收哪些 / 新埋哪些
- 角色关系变化

**c) 场景规划（含篇幅占比）**

🔴 每章场景围绕**"搭戏→唱戏→高潮→结尾"**弧线展开，但**不是死板的四段式**——根据剧情需要灵活组合，可以多段唱戏交替、搭戏直接接高潮、甚至整章都是一个大高潮的不同阶段。核心是**每章要有完整的情绪弧线**（有起有落有收），而不是机械地各填一段。

**搭戏**（场景构建，建议占比10%-20%）
- **核心任务**：用最短篇幅让读者进入情境——地点在哪、谁在场、气氛如何
- **写法**：直接切入事件（如"门被踹开，一个身影冲进来"），用动作/对话带出环境，禁止长篇背景介绍或景物描写开场
- **灵活运用**：紧张剧情可省略搭戏直入冲突；日常章节搭戏可稍长，用轻松氛围做缓冲；也可以用上一章结尾的悬念作为搭戏的切入点

**唱戏**（剧情发展，建议占比20%-35%/段，可多段）
- **核心任务**：推进剧情、发展人物关系、埋伏笔、拉高冲突张力
- **写法**：通过人物互动（对话+行动）推动事件，每段唱戏都要有**目的**（获取线索/暴露矛盾/建立关系）和**障碍**（有人阻挠/信息不足/内心挣扎），用行动代替说教
- **灵活运用**：一章中可以有多段唱戏（不同子事件交替推进）；节奏快的章节唱戏压缩、直奔高潮；铺垫章节唱戏可占大头，重心放在埋线和人物刻画

**高潮**（情绪爆发，建议占比25%-40%）
- **核心任务**：本章的情绪顶点——打脸/战斗/揭秘/反转，满足读者的爽感期待
- **写法**：对抗性要强（不是主角说句狠话就完了，要有实际交锋和结果）；用配角反应（震惊/佩服/恐惧）放大爽感；反差越大越爽（越被看不起→反击越猛）
- **灵活运用**：不是每章都需要大高潮，铺垫/过渡章节的"高潮"可以是一个小揭秘或关系转折；连续高潮章节要注意情绪递进而非平铺；悬念驱动型章节的高潮可以是一个惊人真相而非打斗

**结尾**（收束+钩子，建议占比10%-20%）
- **核心任务**：当前事件落幕 + 抛出下章钩子，让读者忍不住翻页
- **写法**：先给反应节拍（角色对高潮事件的反应——"他握紧拳头"、内心独白等），再引出新悬念或新威胁
- **灵活运用**：钩子形式多样——可以是反派的反扑预告、新角色登场、秘密被部分揭露、主角新的抉择；日常章节结尾可以用一个突发事件打破平静

每个场景须明确：**切入方式**（怎么开始）、**目的**（推动什么）、**障碍**（冲突/阻力）、**结果**（解决还是留悬念）、**反应节拍**（角色对场景结果的情绪走向/状态变化——只写大的方向，不写具体内容）

| 场景 | 篇幅占比 | 出场角色 | 情绪走向 | 场景类型 | 反应节拍 |
|------|---------|---------|---------|---------|---------|
| 1. [场景名] | 15% | [角色列表] | [情绪] | 搭戏/唱戏/高潮/结尾 | [角色反应] |
| 2. [场景名] | 30% | [角色列表] | [情绪] | 搭戏/唱戏/高潮/结尾 | [角色反应] |
| ... | ... | ... | ... | ... | ... |
| **合计** | **100%** | | | | |

> 🔴 **反应节拍只是大的方向**：反应节拍列与场景详细规划中的"反应节拍"只写角色场景结束时的**情绪走向/状态变化**（如"陈安：无波澜，稳坐看戏""通天教主：势在必得→惊疑"），**禁止写入任何正文内容**——既禁止带引号的台词/旁白原句，也禁止"内心冷笑""内心吐槽""暗自盘算"等独白式描述。台词与内心独白的措辞全部留给 novel-writer 在写作阶段自由创作。

🔴🔴🔴 **与上一章差异化设计（防雷同，每章设计必须过）**：
> 设计稿的目标是让本章**区别于上一章**，而不是延续上一章的写法。生成设计稿前**必须先读上一章 design.md + content.md**，做差异化比对，本章设计在以下维度刻意求变：

- 🔴 **结尾意象/钩子不得复用**：本章结尾的收束意象、比喻系统、钩子形式必须与上一章（及近 2~3 章）**不同**。禁止出现"与第N章结尾形成跨章呼应"之类的指令，也禁止在场景结果/反应节拍中复用上一章的修辞意象（如上一章用"开锣声/戏台/翻页"，本章换"药/方士/器物/灯火"等其他物象）。写作硬约束中可加一条"🔴 禁止复用第N章的 XX 意象"作显式提醒
- 🔴 **反应节拍不得复制**：反应节拍写情绪方向（如"警觉转期待"），**禁止**直接把上一章的节拍措辞照搬或改字复用
- 🔴 **开场方式求变**：开场切入方式与上一章不同（上一章动作开场，本章可对话/氛围/悬念开场；上一章搭戏较长，本章可直入冲突），避免章章一个模板
- 🔴 **场景结构求变**：场景组合与上一章错开（上章四段式，本章可双线交替/整章高潮等），节奏不重复
- 🔴 **爽点/冲突类型轮换**：本章核心爽点类型（打脸/揭秘/反差/收获）尽量与上一章错开，避免连续同款
- ✅ **可保留的"呼应"**：真·剧情伏笔的回响（约定信物、重复出现的物品、前后呼应的台词）属于蓄意设计，不算雷同，可保留——但要用**剧情**呼应，不是**修辞意象**复制
- ✅ 生成后自检：本章设计稿通读一遍，若发现与上一章设计稿多处措辞/意象/结构雷同 → 回改

🔴 **场景类型组合灵活**：不必每章都是"1搭戏+1唱戏+1高潮+1结尾"的固定四场景。根据剧情需要，可以是"搭戏→唱戏→唱戏→高潮→结尾"（双线交替）、"搭戏→高潮→结尾"（快节奏章）、"唱戏→唱戏→唱戏→结尾"（纯铺垫章）等。关键是整章有**情绪弧线**。

🔴 **设计稿只负责篇幅节奏分配**：场景表格使用百分比，不要求精确到具体字数；正文最终硬约束以 **`.dsh/config.yaml` 的 `wordCount` 段（缺省 2000-3500字）** 为准。

🔴 **出场角色标记规则**：
- **命名角色**（有名字、有对话/行动、推动剧情的角色）→ 直接写名字，无论是否已有设定文件。新命名角色在校验 ERROR 时创建设定文件
- **泛称/背景角色**（无名的功能性存在，如技术员、哨兵、士兵）→ 用 `~波浪号~` 包裹，如 `~技术员~`、`~哨兵~`，脚本校验时自动跳过
- 🔴 **命名 vs 泛称的判断标准（含复用性维度）**：
  1. 有台词、有名字、推动剧情发展 → **命名角色**
  2. **本章戏份少但后续剧情会复用**（线人、常驻店主、特定组织成员等）→ **也应命名建档**，为后续回收留钩子；不得因为"本章只是路过"就压成 `~泛称~`
  3. 真正一次性、可替换的背景存在（围观人群、某次对话的陌生店员）→ `~泛称~`
- 🔴 **新角色引入节奏自检**（设计稿完成后逐条核对）：
  - 单场戏同时出现的有名字角色 ≤ 4~5 个，其余用身份称呼
  - 本章新引入的命名角色 ≤ 2 个为宜（大纲明确要求除外）；开篇前 3 章新角色总量建议 3 个左右
  - 贯穿配角不每章都出场；上一章已密集登场则本章可让其缺席，留出期待空间
  - 连续多章无新角色 / 本章新角色过密时，在设计稿中标注节奏意图，供校验提示

**d) 设定增量**
- 本章新增的设定（需写入宪法的标注 `[需更新宪法]`）

**e) 创作避毒指南自检**
🔴 **设计稿生成后，必须检查 `novel/outline.md` 头部的「创作约束」段落，逐条核对所有场景设计是否违反审核红线和避毒指南。发现违反即修正场景设计，不可放过。**
- 创作约束包括：平台审核红线、本书特有的避毒指南
- 自检范围：每个场景的出场角色行为、信息获取方式、能力使用是否符合约束

### 4. 脚本校验设计稿


校验项：
- 场景表格使用**篇幅占比**并能形成完整节奏结构（脚本会校验表格结构、场景数与占比信息）
- 出场角色全部在 novel/constitution/characters/ 目录中有对应文件（`~泛称~` 格式的角色自动跳过）

  **角色文件缺失 ERROR**：

  1. **命名角色**（有名字、有对话、推动剧情、大纲提到）→ 在 `novel/constitution/characters/` 下创建设定文件，展示给用户确认

### 4.1 跨章重复/意象雷同自检（默认执行）

🔴 设计稿除通过脚本校验外，还必须通过"跨章重复/意象雷同"自检（主流程直接完成，无需 SubAgent；与 3b 的"与上一章差异化设计"配套，把防雷同从写作规则升级为校验项）：

- **输入**：N-1 章 `design.md`（步骤1已加载）；按需再读 N-2/N-3 章 `design.md` 的结尾场景与开场方式
- **逐项比对本章设计稿**：
  1. 🔴 **结尾意象/钩子不得复用**：收束意象、比喻系统、钩子形式与上一章（及近 2~3 章）不同（如近章用过"开锣声/戏台/翻页"，本章换"药/器物/灯火"等其他物象）
  2. 🔴 **开场方式/场景结构求变**：与上一章错开（上章动作开场本章可对话/氛围/悬念开场；上章四段式本章可双线交替/整章高潮）
  3. 🔴 **反应节拍不得复制**：禁止照搬或改字复用上一章的反应节拍措辞
  4. 🔴 **钩子类型轮换**：连续多章章末钩子类型单一（如都是"XX来了"式悬念）→ WARNING
- **判定**：完全复制近章收束句式/意象/节拍措辞 → CRITICAL（回改设计稿相应场景）；近似复用/钩子同质化 → WARNING（最小修正）

- 自检未通过 → 回改设计稿后重新执行步骤 4 脚本校验 + 本步骤；通过 → 步骤4.5

### 4.5 设计稿语义校验（continuity-validator，stage=design）（默认执行）

🔴 **脚本校验只查格式合法性**（表格/角色/伏笔），**不查内容合理性**。设计稿语义层面（大纲覆盖、前文衔接、宪法合规、伏笔因果、文风）必须由 AI 语义校验兜底，与批量模式 Step A2 对齐。

🔴 **默认执行，无需任何参数**：设计稿脚本校验（步骤4）通过后，**必须**启动 SubAgent `continuity-validator`（stage=design）做语义校验；`--deep` 为历史兼容参数，行为与默认一致。

调用 SubAgent `continuity-validator`，使用 `stage=design`：

```
执行设计稿连续性校验。
stage: design
chapter: {N}
请严格按照你的 <context_loading> 规则自行加载所有必要上下文。
```

校验重点（与批量 Step A2 一致）：
- 🔴 **大纲覆盖度**：从 `outline.md` 提取本章事件/目标，逐条检查 design.md 是否安排对应场景；大纲事件被遗漏 → CRITICAL
- 🔴 **偏航预警**：设计稿新增大纲未提及的重大事件 → WARNING
- 时间线是否与上一章 / `state.yaml` / `outline.md` 连续
- 角色位置、伤势、知情边界是否合理
- 数值链 / 库存链 / 装备来源是否自洽
- 伏笔安排是否可执行、是否误回收/漏回收
- **宪法合规**：设计稿场景是否违反 core.md 的 `[不可变]` 规则
- **文风传导**：设计稿"写作硬约束"是否已从 style.md 提取核心文风约束（见 batch-designer 规则）
- **跨章重复/意象雷同（validator 复查 4.1 自检结果）**：design.md 是否出现"与第N章结尾形成跨章呼应"之类的指令，或写死了与近章相同的修辞意象/收束方式 → WARNING（设计稿不应指定具体意象复用，正文创作应自由换新）

结果处理（默认执行）：
- **CRITICAL / ERROR** → 主会话读取 `design.md`、验证报告和必要上下文，按 `main-repair` 做最小回修；修复后重新执行 `validate-design.ps1` + `continuity-validator(stage=design)`，直到非 CRITICAL
- **WARNING** → 判断是否影响正文实现：影响则最小回修；observe-only（可自圆其说）则记录
- **PASS** → 进入步骤5

### 5. 写入设计稿

写入 `novel/chapters/[N]/design.md`

🔴 写入后流程即结束，不再等待确认。如对设计稿不满意：
- 直接手动编辑 `design.md`
- 或重新执行 `/novel-design N` 并附修改意见

### 6. 提示下一步

```
第N章设计完成（脚本校验 + continuity-validator 语义校验双重通过）。下一步：
- 开始写作：/novel-write N（🔴 设计稿已在设计阶段通过双重校验；写作阶段不再重复校验设计稿）
- 调整设计：/novel-design N
```

## 约束

- 🔴 **所有章节路径使用三位数补零格式**：`novel/chapters/001/`、`novel/chapters/052/`（即 `{0:D3}` 格式），包括设计稿路径 `novel/chapters/[NNN]/design.md`
- 🔴 场景规划表格必须使用**篇幅占比**字段（推荐合计约100%），用于节奏分配而非机械卡字数
- 🔴 不得在设计阶段写正文内容：设计稿只允许描述**方向/意图/情绪**；🔴 "反应节拍"只是大的方向——只写角色情绪走向/状态变化（如"陈安：无波澜，稳坐看戏"），**禁止写入带引号的台词原句，也禁止"内心冷笑""内心独白"等独白式描述**；台词与内心独白措辞全部留给写作阶段自由创作
- 🔴 出场角色必须在 novel/constitution/characters/ 中有对应文件（`~泛称~` 格式的背景角色除外，脚本自动跳过）
- 🔴 伏笔回收必须引用 novel/state.yaml 中的伏笔 ID
- 🔴 大纲和设计稿都是 Agent 生成草稿模式，生成后直接落盘，不设中间确认
- 🔴 **单章设计稿生成前必须先执行 `create-design-template.ps1 -Chapter N -Force` 生成合规骨架，在骨架基础上填充**，禁止从零手写格式（骨架格式即 validate-design.ps1 的解析格式）
- 🔴 用户任何引导步骤都可以"跳过"，Agent 用合理默认值填充
- 🔴 每章设计稿默认执行双重校验：脚本校验（validate-design.ps1）+ 语义校验（continuity-validator stage=design），双重通过才可进入写作；`--deep` 为历史兼容参数，行为与默认一致
