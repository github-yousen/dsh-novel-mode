# agent-skeleton-rebuilder

<objective>
在独立上下文中，读取拆书报告的骨架DNA + 用户确认的换皮设定，生成一套全新的小说宪法（novel/constitution/）和全书大纲（novel/outline.md），使新书在结构/节奏/技巧层面继承源书优点，但在内容层面与源书完全不同。
</objective>

<context_loading>
🔴 **只读拆书报告和换皮设定，不读源书原文**

主流程传入参数：
- `report_path`: 拆书报告路径（novel/source/report.md）
- `user_settings`: 用户在 Phase 5 确认的换皮设定（JSON 格式）
  - `genre`: 目标类型
  - `world_setting`: 世界观要点
  - `protagonist`: 主角设定
  - `characters`: 其他角色设定列表
  - `power_type`: 金手指类型
  - `protagonist_start`: 主角起点模式
  - `conflict_path`: 冲突升级路径
  - `style_preference`: 风格偏好
  - `target_chapters`: 新书目标总章数（用户在 Phase 5 指定）
  - `plan_range`: 本次规划范围（如 `1-100`，分段规划时 ≠ target_chapters）
  - `plan_mode`: 规划模式（`full` 全部规划 / `staged` 分段规划）
- `template_dir`: 模板目录路径

SubAgent 启动后加载：
1. `novel/source/report.md` — 拆书总报告（~2000字，骨架DNA）
2. 用户换皮设定（~500字，主流程传入）
3. 类型预设模板（~300字，按 genre 加载对应预设）
4. 宪法模板 `.dsh/templates/constitution/`（~300字）
5. 章节级规划结构要求（~300字，从当前项目规则中归纳）

总上下文 ≈ 3500字（非常轻量）
</context_loading>

<steps>
1) 读取拆书报告，提取骨架DNA：
   - 主线结构模式（阶段数、每阶段章数比例、推进逻辑类型）
   - 节奏模式（爽点周期、张弛比、情绪曲线类型）
   - 钩子编排模式（类型分布比例、回收周期）
   - 角色功能矩阵（功能位、出场时序、关系弧模式）
   - 金手指模式（能力类型、限制类型、升级节奏）
   - 爽点公式库（公式骨架、四要素覆盖模式）

2) 生成新宪法 — `novel/constitution/core.md`：
   
   根据用户选择的类型和世界观要点，结合类型预设：
   - 时代背景（全新创作，与源书无任何关系）
   - 核心规则（基于用户指定的金手指类型设计力量体系）
   - 地理设定（全新世界地理）
   - 机器校验规则（冲突正则）
   - 🔴 控制在 1500-2000 字，聚焦 [不可变] 硬规则与核心世界观

3) 生成新宪法 — `novel/constitution/style.md`：
   
   🔴 **重点参考拆书报告「五、写作风格指纹」中的完整风格档案**，将源书的文笔特征转化为新书的写作约束。根据用户偏好可调整，但默认尽量继承源书风格：
   
   - 叙事人称/时态
   - 对话格式
   - 语言基调
   - **句式节奏约束**：从风格档案的"句式节奏"提取，如"战斗场景使用短句连击，过渡段用长句放缓"
   - **描写偏好约束**：从风格档案的"描写偏好"提取，如"心理描写靠行为暗示，不用大段独白"
   - **对话风格约束**：从风格档案的"对话风格"提取，如"短对话为主，用动作tag替代说字"
   - **情绪渲染约束**：从风格档案的"情绪渲染"提取，如"不直说情绪，用行为+环境间接传达"
   - **语言调性约束**：从风格档案的"语言调性"提取，如"整体冷硬克制，搞笑靠反差"
   - 🔴 这些约束是后续 `novel-writer` 写作时的直接参考依据
   - 🔴 控制在 1500-2000 字

4) 生成新角色 — `novel/constitution/characters/[角色名].md`：
   
   根据拆书报告的角色功能矩阵，为每个功能位创建角色：
   - 🔴 **必须读取模板** `.dsh/templates/constitution/characters/_template.md`，严格按照模板格式生成
   - 保留功能定位（导师/宿敌/红颜...）和行为模式标签
   - 填入用户在 Phase 5 提供的新角色信息
   - 每个角色：性格内核、说话风格、口头禅、外貌特征、初始位置、关系网、状态
   - 🔴 文件末尾必须包含 `## 演化记录` 段（初始为空，由 chapter-summarizer 每章自动追加）
   - 🔴 角色之间的关系弧参考源书的"关系变化模式"，但用全新的因果逻辑

5) 生成新大纲 — `novel/outline.md`：
   
   🔴 **核心：骨架映射 + 内容全新**
   - 先写 `## 创作约束` 头部（平台审核红线 + 本书避毒指南 + 豁免项），作为后续 `batch-designer` / `novel-writer` / `continuity-validator` 的权威约束来源
   - 🔴 `outline.md` 头部创作约束与 `core.md` 的 `[不可变]` 硬设定是两套规则源，必须同时保留


   **规模差异处理**（源书章数 ≠ 新书目标章数时）：
   - 🔴 骨架DNA是**比例和模式**（如"3段30%+40%+30%"），不是绝对章数
   - 源书50章 → 新书500章：阶段比例不变，但每阶段内部的爽点周期、伏笔密度按新规模等比放大
   - 具体映射规则：
     - 阶段比例：保持源书比例（如30:40:30），按 `target_chapters` 计算实际章数
     - 爽点周期：源书每5章一个爽点 → 新书同样保持每5章一个爽点（周期不变，总量增加）
     - 伏笔密度：按新规模重新分配，长篇允许更多长线伏笔
     - 角色出场：比例位置不变（如"30%处引入宿敌"），实际章节号按新规模换算

   **分段规划处理**（`plan_mode == staged` 时）：
   - 大纲只展开 `plan_range` 指定的章节范围（如第1-100章）
   - 但必须先生成 `## 全书走向（粗纲）` 段，覆盖全部 `target_chapters` 的走向
   - 大纲头部填写规划元数据：
     ```
     **预计总章数**: 500
     **当前已规划**: 第1-100章
     **规划模式**: 分段规划
     ```
   - 大纲末尾添加待追加分割线

   a) 结构映射：
      - 按源书阶段比例分配新书的卷/章结构
      - 例：源书是 3段（30%+40%+30%），新书也按此比例
      - 每卷命名和目标完全基于新设定创作

   b) 节奏映射：
      - 按源书爽点周期在新大纲中标记爽点位置
      - 按源书张弛比安排高潮和过渡的分布
      - 情绪曲线保持相同形态（波浪型/递进型/...）
   
   c) 钩子映射：
      - 按源书钩子类型分布，在新大纲中规划每章钩子类型
      - 伏笔按源书的埋设-回收周期规划新伏笔
      - 🔴 伏笔内容必须完全原创

   d) 角色映射：
      - 按源书角色出场时序安排新角色出场
      - 按源书关系弧模式规划新的关系发展
      - 🔴 具体事件必须完全原创

   e) 爽点映射：
      - 按源书爽点公式库，在对应位置安排相同公式骨架的爽点
      - 但填入全新的场景和角色
      - 例：源书"被轻视→反转→震惊"公式在第4章
        → 新书第4章也安排一个"被轻视→反转→震惊"，但场景/角色/冲突全新

   f) 每章生成：
      - 一行梗概（≤50字，全新创作）
      - 节奏标注（铺垫/上升/高潮/过渡/低谷）
      - 关键事件标注（🔥转折 ⭐高潮）
      - 伏笔标注（📌埋设 ✅回收）
      - 钩子类型标注

   g) 🔴 **网文开篇铁律**（必须遵守）：
      - 第1章第1段主角必须出场
      - 前3章完成：主角出场 → 金手指亮相 → 首次小爽点
      - 打脸/冲突周期 ≤ 5章
      - 第一卷节奏最快，1章2-3场景

6) 返回给主流程：
   ```
   宪法文件: X个
   角色数量: X个
   大纲章数: X章（已规划范围）
   总目标: X章
   规划模式: 全部规划 / 分段规划
   分卷: X卷（已规划范围内）
   伏笔数: X个
   源书骨架继承项: [节奏模式/钩子分布/爽点公式/角色时序]
   ```
</steps>

<anti_plagiarism_rules>
🔴 **贯穿全程的反抄袭检查清单**：

生成任何内容前，必须自检：

1. **名词检查**：新内容中是否出现了源书报告中标记的任何专有名词？→ 必须为 0
2. **场景检查**：新大纲的章节梗概是否能直接对应到源书某个具体场景？→ 如果能，必须重写
3. **关系检查**：新角色的关系发展是否与源书角色的关系发展在细节上高度一致？→ 模式可以相似，但具体事件必须不同
4. **因果检查**：新大纲中的因果链条是否与源书的因果链条逐环对应？→ 允许局部结构相似，但不允许全链条复制
5. **金手指检查**：新金手指的具体表现是否只是源书金手指的"换名"？→ 必须有实质差异

如果任何检查项不通过，在该内容旁标注 `[!SIMILARITY WARNING]` 并提出替代方案。
</anti_plagiarism_rules>

<constraints>
- 🔴 **绝对禁止**读取 `novel/source/chapters/` 中的源书原文
- 🔴 只能读取 `novel/source/report.md`（拆书报告，已去除具体内容）
- 🔴 不与用户交互，仅返回结果给主流程
- 🔴 生成的所有文件必须符合现有 Novel-Spec 标准格式
- 🔴 core.md ≤ 2000字，style.md ≤ 2000字
- 🔴 大纲格式必须与 `/novel-design all` 输出一致，可直接被 `/novel-design N` 消费
- 🔴 角色文件格式必须与 `/novel-constitution` 输出一致，可直接被 `novel-writer` 加载
- 🔴 伏笔 ID 格式统一为 `F-[章节号]-[序号]`
</constraints>
