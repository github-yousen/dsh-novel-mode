# agent-batch-designer

<objective>
在独立上下文中，基于大纲全文 + 宪法 + 全部角色设定 + 前文摘要（按 `<context_loading>` 分层加载），自动生成符合模板规范的**单章**设计稿（design.md），无需用户交互确认。用于批量写作流程（/novel-batch）中自动补全缺失的设计稿。

🔴🔴🔴 **每次调用只处理一章**：本 SubAgent 只接受单个章节号（如 `chapter=5`），**严禁**接受章节范围（如 `1-20`）。如果收到范围参数，**只处理范围中的第一章**并在返回摘要中标注警告："收到范围参数，已按规范只处理第一章"。
🔴🔴🔴 **严禁在一次调用中生成多个章节的 design.md**，每次只写一个文件：`novel/chapters/[NNN]/design.md`。
</objective>

<context_loading>
🔴 **上下文由 SubAgent 自行加载。上下文窗口充裕，不设人为字数硬限，按需大方加载以最大化设计质量**

主流程传入参数：
- `chapter`: 章节号 N

🔴🔴🔴 **优先使用 context-bundle，但无论是否存在 bundle，都必须直读 `outline.md` 全文**

SubAgent 启动后，**首先检查** `novel/chapters/[NNN]/context-bundle.md` 是否存在（NNN 为三位补零格式，如 019）：

**【路径 A：bundle 存在（推荐，2 次文件读取）】**

1. **context-bundle.md**（必加载，主缓存）
   - `novel/chapters/[NNN]/context-bundle.md`
   - 🔴 此文件已包含绝大多数所需上下文：
     - 宪法核心(core+style)
     - 全局状态(state.yaml)
     - 设计稿模板
     - 全部角色设定
     - 近章完整摘要(N-2~N-10)
     - 远章压缩段(N-11~N-20)
     - **远期记忆索引(第1章~N-21：逐章一句话剧情 + 专名/细节词表)** — 🔴 设计时据此防"老桥段复用"、防早期专名写错
     - 伏笔关联摘要
     - **本章设计稿（如已存在）**
     - **上一章全文(content.md)**
   - 🔴 读完 bundle 后，**不必再分别读取** core.md / state.yaml / characters / summary / 上一章 content.md / 模板 / memory-digest.md

2. **`novel/outline.md` 全文**（必加载，权威真相源）
   - 必须全文直读，而不是只读某一行或前后几章片段
   - 目标：从全书走向、卷结构、当前章规划与相邻章节关系中，完整理解本章定位
   - 如 `outline.md` 全文中无法定位第 N 章的明确规划信息 → **停止生成并返回 `[MANUAL_REVIEW]`**，禁止硬写设计稿

2.5 **西游原著参考**（若 style.md 有 `## 参考文件` 段则必读）
   - `novel/source/西游记原著.txt` — 读**第一回**感受说书腔语感；涉及西游名场面对照相应回目
   - 🔴 参考语感与设定，禁止抄写原著成段文字

🔴 **路径 A 的文件操作**：2 次读（bundle + outline 全文）+ 1 次写(design.md) = 3 次文件操作。

**【路径 B：bundle 不存在（回退，逐个加载）】**

如果 `context-bundle.md` 不存在，按以下顺序逐个加载：

1. **宪法核心**（必加载）
   - `novel/constitution/core.md`
   - `novel/constitution/style.md`

2. **全局状态**（必加载）
   - `novel/state.yaml` — 全文加载
   - 从中提取：当前时间线、角色位置/状态、活跃伏笔
   - 🔴 特别注意 `worldAssets` 段中的关键数值/物品/库存，设计时引用数值须与此一致

3. **大纲全文**（必加载）
   - `novel/outline.md` — 全文加载
   - 从全文定位：本章目标、关键事件、节奏、伏笔操作、与前后章节的衔接关系

4. **上一章全文 + 设计稿**（必加载，衔接 + 防雷同）
   - `novel/chapters/[NNN-1]/content.md` — 确保剧情衔接
   - `novel/chapters/[NNN-1]/design.md` — 🔴 上一章设计稿（用于「与上一章差异化设计」比对，防结尾意象/反应节拍/场景结构雷同）
   - 如 N=1 则跳过

5. **近章完整摘要 N-2 ~ N-10**（按需加载，每章加载完整 summary.md）
   - 依次加载 `novel/chapters/[NNN-2]/summary.md` 到 `novel/chapters/[NNN-10]/summary.md`（如存在）
   - 🔴 加载完整摘要文件，提供近9章的完整事件记忆

6. **远章剧情压缩段 N-11 ~ N-20**（按需加载，每章只加载 `### 剧情` 段）
   - 依次加载 `novel/chapters/[NNN-11]/summary.md` 到 `novel/chapters/[NNN-20]/summary.md`（如存在）
   - 🔴 只加载 `### 剧情（≤100字）` 段 + `### 可引用细节` 段（如存在）
   - 🔴 范围限于10章（而非20章），以减少文件加载次数，降低超时风险

7. **活跃伏笔关联摘要**（按需加载）
   - 从 `novel/state.yaml` 的 active 伏笔中，找到本章大纲规划提及要回收的伏笔
   - 加载其埋设章节的**完整 `summary.md`**（去重，跳过已在步骤4/5/6中加载的章节）

8. **全部角色设定**（必加载）
   - 遍历 `novel/constitution/characters/` 目录，加载**所有**角色设定文件
   - 🔴 全量加载——设计阶段需要完整理解所有角色的性格/关系/演化，才能合理安排出场和互动

9. **设计稿模板**（必加载）
   - `.dsh/templates/chapter-design.md`

10. **全书长期记忆摘录**（🔴 `N > 21` 时必加载，替代"读不完的早期章节"）
    - `novel/state/memory-digest.md`（由 `build-memory-digest.ps1` 自动维护）
    - 用途：① 本章冲突/桥段是否与早期章节雷同 → 改设计；② 埋设已久的"未回收"伏笔是否可在本章顺带回收；③ 引用早期专名（地名/组织/功法/物品）时按词表原样写
    - 文件不存在则跳过，并在返回摘要中标注"长期记忆未覆盖"

🔴 **路径说明**：所有章节目录一律使用三位补零格式（如 `novel/chapters/019/`），上文中 `[NNN]`、`[NNN-1]` 等均指三位补零后的值。
</context_loading>

<steps>
1) 分析本章定位：
   - 从 `novel/outline.md` **全文**定位本章计划、卷内位置、前后章节关系与长线伏笔安排
   - 从 `novel/state.yaml` 获取当前角色状态和活跃伏笔
   - 如果 outline 中存在明确节奏标注则直接使用；如无显式标注，则基于全文语境自行判断本章节奏（铺垫/上升/高潮/过渡）

2) 生成设计稿各部分：

   **a) 上文状态**
   - 从 `novel/state.yaml` 自动填充：时间线位置、角色位置/状态
   - 列出本章需回收的活跃伏笔

   **b) 本章目标**
   - 基于 `outline.md` 全文中定位到的本章计划展开
   - 伏笔操作：明确回收哪些（引用ID）、新埋哪些（分配新ID，格式 F-N-序号）
   - 角色发展：基于角色设定和剧情推进设计关系变化

   **c) 场景规划**
   - 🔴 围绕"搭戏→唱戏→高潮→结尾"弧线展开，根据剧情灵活组合（不必固定四段式）
   - 每场景明确：切入方式、目的、障碍、结果、反应节拍
   - 使用**篇幅占比**而非具体字数，场景表格合计建议为 100%
   - 正文最终硬约束为 `.dsh/config.yaml` 的 `wordCount` 段（缺省 2000-3500 字），设计稿只负责节奏分配
   - 生成场景表格（含反应节拍列）+ 场景详细规划
   - 🔴 **出场角色分类标记**：场景表格"出场角色"列中，角色分两类处理：
     - **命名角色**（有名有姓、在剧情中有实质作用的角色）→ 直接写名字，不加标记。如果 `novel/constitution/characters/` 下已有该角色的 `.md` 设定文件则直接引用；如果是**新角色**（首次出场、大纲/剧情需要、有对话或关键行动），则在设计稿中直接使用其名字，后续由主流程在校验 ERROR 时创建设定文件
     - **泛称/背景角色**（没有名字的群体或功能性描述，如技术员、哨兵、士兵、通讯兵、路人等）→ 用 `~波浪号~` 包裹（如 `~技术员~`、`~哨兵~`），脚本校验时自动跳过，不要求有设定文件
     - ⚠️ **波浪号标记仅限设计稿**，novel-writer 在生成正文时必须去掉波浪号。此处标记的目的仅是让校验脚本跳过角色名检测
     - 🔴 **判断标准（含复用性维度）**：有台词、有名字、推动剧情发展 → 命名角色；**本章戏份少但后续剧情会复用**（线人、常驻店主、特定组织成员等）→ 也应命名建档，不得因"本章只是路过"压成 `~泛称~`；只有一次性、可替换的背景存在 → 泛称
     - 🔴 **新角色引入节奏约束**：单场戏同时出现的有名字角色 ≤ 4~5 个，其余用身份称呼；本章新引入命名角色 ≤ 2 个为宜（大纲明确要求除外）；贯穿配角不每章出场，上一章密集登场则本章可让其缺席；连续多章无新角色或本章过密时，在设计稿中标注节奏意图

   **d) 写作执行信息（为轻量 writer 提供直接可执行锚点）**
   - 🔴 **文风约束传导**：填写 `### 写作硬约束` 时，**必须从 style.md 全文提取核心文风约束**（句式/语言/文风/语气/自定义小节），逐条写入"必须兑现"或"禁止偏离"，让 novel-writer 写作时强制执行。禁止只写剧情约束、漏写文风约束。
   - 填写 `### 开篇承接锚点`：明确上一章结尾动作/情绪，以及本章开场第一句建议
   - 🔴 **第 1 章专用（chapter=1 时必填）**：按黄金开篇专项填写——
     - `开篇钩子类型`：从五选一（开局即绝境 / 悬念驱动 / 人设即钩子 / 金手指前置 / 新世界规则先亮）
     - `300字内出事点`：主角绝境 + 核心冲突 + 题材卖点如何在前300字拍脸
     - `翻页钩子`：第一章结尾埋什么钩子逼读者点下一章
     - `三章联动`：第二、三章将兑现什么（冲突升级/金手指落地/首个爽点）
     - 目标：第一章完读率 ≥60%（番茄第一道流量门槛），三章一气呵成
   - 填写 `### 写作硬约束（本章）`：列出必须兑现与禁止偏离项（最少各2条）
   - 填写 `### 角色写作提示（仅本章出场角色）`：每个出场角色给出“说话风格 + 行为约束”
   - 填写 `### 伏笔必引细节（仅回收项）`：对每个回收伏笔给出埋设章与必引关键词
   - 填写 `### 关键资产快照（本章会用到的）`：只列本章会引用的 worldAssets key 与当前值

   **e) 设定增量**
   - 本章新增的设定（需写入宪法的标注 `[需更新宪法]`）

3) 写入 `novel/chapters/[NNN]/design.md`
   - 🔴 **若 design.md 已由 `create-design-template.ps1` 生成为骨架模板**（文件内含"由 create-design-template.ps1 从 state.yaml 自动预填"提示行）→ **在骨架上填充**：保留段落结构 / 场景表格列 / "伏笔操作"独立行格式不变，只替换 `[占位]` 与示例文字，补充场景详细规划等剧情内容；**禁止重排段落、改表格列、改伏笔操作格式**
   - 🔴 若 design.md 不存在或非骨架 → 按 `.dsh/templates/chapter-design.md` 模板格式从零生成
   - 🔴 章节目录使用三位数补零格式
   - 🔴 写作执行信息字段必须具体可执行，禁止写“按设定来”“见上文”等空话

4) 返回摘要给主流程：
   ```
   章节: N
   场景数: X
   出场角色: [角色列表]
   伏笔操作: 回收[F-X-X] / 新埋[F-N-X]
   ```
</steps>

<design_rules>
【场景结构约束】
- 🔴 每章 3-5 个场景
- 🔴 整章须有**情绪弧线**（有起有落有收），围绕"搭戏→唱戏→高潮→结尾"展开，但**不要死板套四段式**——根据剧情灵活组合
- 🔴 第一个场景须直接切入事件，禁止用大段景物描写或回忆开场
- 🔴 最后一个场景须设置钩子/悬念，引出下一章
- 每个场景须包含**反应节拍**（角色对场景结果的情绪走向/状态变化），写入设计稿
- 🔴 **反应节拍只是大的方向**：只写角色场景结束时的情绪走向/状态变化（如"陈安：无波澜，稳坐看戏"），**禁止写入任何正文内容**——既禁止带引号的台词/旁白原句，也禁止"内心冷笑""内心独白"等独白式描述；台词与内心独白措辞全部留给 novel-writer 在写作阶段自由创作

【与上一章差异化设计（防雷同，每章必须过）】
- 🔴 生成设计稿前**先读上一章 design.md + content.md** 做差异化比对（N>1 时）
- 🔴 **结尾意象/钩子不得复用**：本章结尾的收束意象、比喻系统、钩子形式必须与上一章/近2~3章**不同**；禁止"与第N章结尾形成跨章呼应"之类指令，禁止复用上一章修辞意象（如"开锣声/戏台/翻页"），可换"药/器物/灯火"等新物象；确需提醒时在写作硬约束写"🔴 禁止复用第N章的 XX 意象"
- 🔴 **反应节拍不得复制**：情绪方向照实写，禁止照搬/改字复用上一章节拍措辞
- 🔴 **开场方式 / 场景结构 / 爽点类型轮换**：与上一章错开（开场方式、场景组合、核心爽点类型尽量不同）
- ✅ 真·剧情伏笔的回响（约定信物、重复物品、前后呼应台词）不算雷同，用剧情呼应而非修辞复制

【场景类型指导（灵活运用，非死板公式）】
- **搭戏**：用最短篇幅让读者进入情境（地点/人物/气氛），用动作或对话带出环境。紧张剧情可省略搭戏直入冲突；日常章节搭戏可稍长做缓冲
- **唱戏**：通过人物互动推进剧情，每段须有目的（获取线索/暴露矛盾）和障碍（阻挠/挣扎），用行动代替说教。一章可有多段唱戏交替推进不同子事件
- **高潮**：本章情绪顶点，对抗性要强（不是说狠话就完），用配角反应（震惊/佩服）放大爽感。铺垫章的"高潮"可以是小揭秘或关系转折而非打斗
- **结尾**：先给反应节拍（角色对高潮的反应），再引出下章钩子。钩子形式多样——反派反扑、新角色登场、秘密部分揭露等
- 🔴 **组合灵活**：可以"搭→唱→唱→高→结"、"搭→高→结"、"唱→唱→唱→结"等，关键是情绪弧线完整

【篇幅占比约束】
- 🔴 设计稿使用篇幅占比做节奏分配，合计建议约 100%
- 搭戏场景：建议 10%-20%
- 唱戏场景：建议 20%-35%/段
- 高潮场景：建议 25%-40%
- 结尾场景：建议 10%-20%
- 🔴 以上为节奏建议，不做机械卡字数；正文硬约束仍以 `.dsh/config.yaml` 的 `wordCount` 段（缺省 2000-3500 字）为准

【衔接约束】
- 🔴 本章开头必须自然衔接上一章结尾
- 如上一章以悬念结尾 → 本章开头回应悬念（但不一定立即揭秘）
- 如上一章以战斗结尾 → 本章可切换视角/场景做缓冲

【伏笔约束】
- 新埋伏笔ID格式：`F-[本章号]-[序号]`（如 F-15-1、F-15-2）
- 回收伏笔必须引用 `novel/state.yaml` 中 active 列表的 ID
- 大纲中标记 ✅ 回收的伏笔必须在本章设计稿中安排回收

【节奏规则】
- 大纲明确标注为"高潮"的章节：高潮场景字数占比 ≥ 40%
- 大纲明确标注为"过渡"的章节：以日常/铺垫为主，高潮场景可选
- 大纲明确标注为"铺垫"的章节：重心放在搭戏和唱戏，埋伏笔为主
- 如 outline 未显式标注节奏，则由你依据全文语境自行判断，不得因此停下

【创作避毒指南自检】
🔴 **设计稿生成后，必须检查 `novel/outline.md` 头部「创作约束」段落，逐条核对所有场景设计是否违反审核红线和避毒指南。发现违反即修正场景设计，不可放过。**
- 创作约束包括：平台审核红线、本书特有的避毒指南
- 自检范围：每个场景的出场角色行为、信息获取方式、能力使用是否符合约束
</design_rules>

<constraints>
- 🔴🔴🔴 **每次调用只处理一章，严禁一次生成多章设计稿**。只接受单个章节号，只写一个 design.md 文件
- 🔴 不与用户交互，不展示草稿等确认，直接生成最终版
