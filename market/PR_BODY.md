**From one idea to a finished, consistency-checked novel — a deterministic writing engine, not a prompt pack.**

小说模式 (Novel Mode) is a production-grade DSH plugin whose intelligence lives in code, not in instructions to the model. `lib/orchestrator.js` is a pure, importable JavaScript state machine: a `STAGE_GRAPH` of 7 gated top-level stages (constitution → outline → design → write → validate → batch → export) plus three bootstrap branches, and a nested strictly-serial 15-step per-chapter `BATCH` sub-FSM.

Gates are **code-enforced**: `stageGuard()` checks artifacts, `gate()` runs the correct per-validator argv (`pwsh -NoProfile -File .dsh/scripts/<validator>.ps1` plus `-Chapter N`, `-All`, or `-StartChapter/-EndChapter` as that script requires) and treats the exit code as the authority. A model cannot skip a stage (`advance()` rejects illegal transitions) and cannot assert a PASS — the Host adapter re-verifies every gate event against the real script verdict. BATCH sub-steps without a validator advance only through the dedicated `step-done` event, never a fabricated PASS. Failures are bounded/classified retries; `DEGRADED` and `PAUSED` are always recorded. A versioned atomic checkpoint under `.dsh/state/` resumes at the exact chapter after a restart and tolerates corruption by backing it up. Nine subagent worker roles receive typed minimal arguments (the dispatcher cannot emit file lists or plot hints) and their findings are **evidence-adjudicated in code** with fixed precedence truth-files > subagent-judgment > engine-memory.

The user surface is deliberately quiet: the `novel_orchestrate` tool returns structured JSON and renders only `阶段 · 第 N 章 · 步骤 X · <generic localized status>`. No persona prose, no workflow brief, no prompt dumps, no stderr, script names, exit codes or exception text ever reach the user. A single short tool-routing section (not a prompt group) tells the model to call the engine; all stage order, gates and quality decisions stay in deterministic code. The package bundles zero credentials (only empty `*.json.template` files), degrades gracefully when `pwsh` is absent, and never touches sessions in other projects.

The shipped worker library remains substantial and is re-counted against this build: 21 runtime skills, 18+ PowerShell/Python validators, 9 subagent roles, 7 Markdown templates + 1 state.yaml skeleton, 2 rule sets. A multi-angle automated test suite — 10 suites / 292 assertions, including a **real-`pwsh`** integration test that executes the bundled validators with the engine's own argv — lives under `test/`; a 5-angle team review and a resident PM acceptance review (AC-1..48, U1–U8) live under `docs/REVIEW-*.md` and `docs/PM-*.md`. Plain JavaScript, no build step, no npm dependencies; requires PowerShell 7 and Python 3.7+. Release **v2.1.0** carries these review fixes.
